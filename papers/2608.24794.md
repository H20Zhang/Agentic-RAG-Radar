# CAFE: Self-Improving Search Agents Need Co-Evolving Feedback

*Published 25 Aug 2026 · Learning & Optimization · Importance 4/5 · Full-text reviewed · Confidence medium*

[Paper](https://arxiv.org/abs/2608.24794)

> **TL;DR.** CAFE makes corrective feedback a learned in-trajectory intervention: the search policy learns when to request it while a shared-parameter critic learns corrections from changing on-policy failures. Against the same feedback-SFT + GRPO setup it reaches **52.5 EM / 60.7 F1** versus **49.7 / 58.0**. The package also changes request shaping, token credit, critic preference learning, and the online/offline alternation schedule; a matched-500-step ablation shows schedule itself materially matters.

## Research question

As a search policy improves, can the corrective critic co-adapt to its shifting failure distribution, and can the agent learn *when* feedback is worth requesting?

## Research delta

CAFE changes feedback from a static trainer-side signal into an action inside the trajectory:

`search → optional request_feedback → critic correction → recovery → outcome`

and then alternates online agent RL with offline critic preference learning from on-policy prefixes.

## Mechanism

A shared Qwen2.5 model alternates agent and critic roles. Feedback-conditioned SFT is bootstrapped from the base agent's own failed prefixes. Online, a Comparative Feedback Estimate uses prompt-level success differences between rollouts that call and skip feedback to shape request returns, while feedback-aware advantage shaping downweights pre-feedback and upweights post-feedback tokens. Offline RDPO trains critic feedback from prefix-matched successful/failed requesting trajectories.

## Evidence & attribution

| Claim | Evidence | Closest control | Assessment |
|---|---|---|---|
| Full CAFE improves search QA | **52.5 EM / 60.7 F1** vs GRPO **49.7 / 58.0** | Same feedback-SFT family | Strong internal package result |
| Beats strongest reproduced RL baseline | IGPO **50.4 / 59.4** | Authors' reproduced checkpoint | Smaller but relevant delta |
| Both online shaping terms help | CFE-only and advantage-only each improve; together are best | Component ablations | Supports both terms |
| Update cadence matters | 500 online steps split 50×10, 100×5, 250×2 give materially different outcomes | Matched online-step count | Major confound |

The paper also reports lower unsupported-claim rate and a positive BrowseComp-Plus fixed-corpus result, but complete realized feedback calls, retrieval calls, tokens, latency, and dollars are not jointly matched.

## Where it fits

`search policy → feedback-request routing → corrective state → recovery → continued retrieval`

This is an `early_signal` that adaptivity can include *when to buy a corrective intervention*. It is not proof that “co-evolution” alone causes the gain.

## Open question

Randomize feedback availability at matched trajectory states, equalize model/tool calls and total tokens, and independently vary request policy, critic quality, and alternation schedule. The key measurement is recovery probability conditional on the same pre-feedback state—not just final average QA.
