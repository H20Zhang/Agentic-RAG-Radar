# LENS：把 Evidence Materialization 推迟到 Query Time

**中文** | [English](2608.16185.md) · [返回首页](../README.md) · [Research Library](../library/README.md)

[Paper](https://arxiv.org/abs/2608.16185) · **Importance: 4/5**

> **Research delta.** LENS 改变的不是“retriever 还是 agent”，而是 **evidence 什么时候才变成具体 retrieval unit**：raw document region 在 query 出现之前保持 latent，之后再按当前 information need 在线定位。

## Problem

传统 indexed RAG 在离线阶段就决定 chunk boundary、embedding/index 与 materialized retrieval unit。对稳定 corpus 很高效，但 query 未知时选的 boundary 不一定适合后来问题，而且 raw document 更新后 index 会产生 freshness lag。

另一极端是 agent 直接搜索 raw files，但如果没有 budgeted localization，很容易退化成昂贵扫描。

## Mechanism

LENS 把 raw-document regions 看成 query-conditioned latent evidence space：

`query → multi-signal prior proposes regions → inspect with relevance oracle → update per-fact beliefs/proposal weights → continue/stop under budget → consolidate grounded evidence → answer`

它真正在线决定的是 evidence boundary 和 exploration path。

## Closest comparison

关键比较包括 fresh/stale indexed RAG 与 index-free ReAct-style raw-document search。这里 ReAct 很重要，因为它证明“零 persistent index”并不等于必须采用 LENS 的特定 belief/proposal machinery。

## Decisive evidence

Controlled D500：

- LENS: **62.4% EM / 84.8% evidence recall**
- ReAct-style search: **65.2% EM / 50.4% evidence recall**

Answer EM 反而略低，但 evidence localization 明显更强。Fixed fullwiki setting 中 answer EM 基本打平，而 grounded answer 更偏向 LENS；论文同时报告 LENS 需要更多 online token/latency。

这说明最稳的 claim 是 **freshness + evidence localization/grounding**，而不是 universal answer-quality win。

## What remains unproven

“zero indexing”不是“zero cost”。真正 decisive 的 systems comparison 应在同一个 changing corpus、同 model、同 answer budget 下，把：

`index build/update + freshness lag` 对比 `online localization + relevance-oracle/controller cost`

一起计入生命周期。

还需要更多 document format、update pattern 与非文本 substrate 来判断 query-time materialization 的适用边界。

## Field-map consequence

LENS 把 `evidence-materialization time` 从 implementation detail 提升为一等设计轴：

`pre-materialized chunk/index ↔ query-conditioned raw-region localization`

它与 adaptivity placement 是正交问题：一个系统可以预先 compile policy，却在线 materialize evidence；也可以反过来。
