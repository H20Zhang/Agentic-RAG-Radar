# Context Compression Cost：省掉的 Context 会不会被 Retrieval 买回来？

**中文** | [English](2608.16370.md) · [返回首页](../README.md) · [Research Library](../library/README.md)

[Paper](https://arxiv.org/abs/2608.16370) · **Importance: 4/5**

> **Research delta.** Context compression 的成本不能只看“prompt 里少了多少 token”。如果被删掉的是之后还能从环境查询到的 state，agent 可能通过额外 retrieval/tool calls 把它重新拿回来。**Retained state 与 reacquisition 是同一个 resource trade-off 的两边。**

## Problem

Agent benchmark 常把 task completion 与 context length 分开报告，于是“更短 context、相同 completion”很容易被解读成免费压缩。

但 long-horizon agent 会反复需要之前看到的环境状态。如果 compression 丢掉这些信息，agent 可以再次 query environment；final completion 可能不变，却产生额外 interaction、latency 与 tool cost。

## Mechanism / measurement design

论文在固定 24-turn horizon 下，把 tool interaction 分成：

- task execution；
- retrieval / state reacquisition。

然后比较 full context、sliding compression、同 compression ratio 的 fact-preserving summary，以及 oracle 把刚被删除的 queryable state 精确恢复的 intervention。

因此它不是提出一个新 retriever，而是在拆一项过去经常被隐藏的 systems cost。

## Closest comparison

最关键的是 `compressed state` vs `oracle-restored dropped state`：两边不是换 agent architecture，而是问**额外 retrieval 是否真的是被丢掉 state 导致**。

ALFWorld 作为 negative boundary 也很重要，因为它没有出现同样的 retrieval surge，说明结论依赖 workload 的 state-reacquisition structure。

## Decisive evidence

在论文的六个 model/regime cell 中，`5×` compression 下 retrieval 都增加，其中五个在 Holm correction 后仍显著，而 completion 变化不显著。

一个代表 cell：GPT-5.5 High 从 **21.0 → 63.9 retrieval calls**，completion 约 **80% → 85%**。

Oracle 恢复 dropped queryable state 后，大部分额外交互消失。这个 intervention 把“compression 让 agent 更笨”与“compression 迫使 agent 重取信息”区分开了一部分。

## What remains unproven

不是所有环境都允许廉价 reacquisition。真实生产系统还需要比较：

`retain state in context / external memory` vs `drop now + pay future tool latency/money`

并考虑 state staleness、tool rate limit、privacy、cache 与 model context pricing。

另外，论文显示 workload dependence 很强，因此不能从一个环境直接推出统一的“最佳 compression ratio”。

## Field-map consequence

它把 context/memory policy 与 retrieval accounting 接到一起：

`state retained → context cost`

`state dropped → possible reacquisition cost`

所以“context compression”不应作为 retrieval system 之外的 runtime detail 单独优化。
