# CTIFoundry: An Agent-Native Corpus Scaffold for Cyber Threat Intelligence

*Published 19 Aug 2026 · Retrieval & Tool Use · Importance 4/5 · Full-text reviewed · Confidence medium*

[Paper](https://arxiv.org/abs/2608.18613)

> **TL;DR.** CTIFoundry materializes official CTI relations, canonical entities, provenance-linked report chunks, and hybrid retrieval, then exposes them through typed resolve/traverse/collect/read tools plus procedural skills. The same stock agent improves substantially over flat-file bash access. The correct attribution is to this coupled scaffold-and-interface package—not to graph structure, a learned controller, or universally cheaper retrieval.

## Research question

If the agent loop and source corpus stay fixed, how much can change when corpus state is materialized into **validated relations, canonical entities, provenance, and typed information-access operations**?

This is earlier than retrieval policy. A controller cannot traverse an authoritative edge, collect all mentioning reports, or verify aliases if those relations are neither represented nor operable.

## Research delta

The smallest delta is an **agent-native corpus scaffold plus action surface**.

- Four authoritative knowledge bases become a deterministic relation graph.
- 321 vendor reports become 688 span-grounded chunks and 4,868 canonical entities with bidirectional provenance indices.
- Dense+lexical search and entity-index access are exposed through seven typed tools.
- Three user-turn procedural skills specialize entity linking, attribution, and multi-document synthesis.

The task-to-skill mapping is static. This is not a learned adaptive controller.

## Mechanism

**Control flow.** `static task playbook → resolve/search → traverse official edges or collect/read reports → verify provenance → answer`

The scaffold contains 6,044 nodes and 7,097 typed official edges. Its operations are `resolve entity`, `get entity`, `ontology neighbors`, `search kb`, `search chunks`, `chunks mentioning`, and `read report`.

Offline extraction uses a model for mentions/TTPs, but identifier validity, edges, and span offsets receive deterministic checks. Query-time tools then expose this persistent state to the unchanged agent harness.

## Evidence & attribution

| Claim | Evidence | Closest control | Assessment |
|---|---|---|---|
| The complete package helps | Four-model F1 gains **+0.190–0.275** | Same stock agent + flat bash corpus | Strong within CTIConnect |
| Tools and skills both matter | gpt-5.4: **0.610 / 0.746 / 0.672 / 0.829** | 2×2 base/tools/skills/full | Strong package decomposition |
| Materialized official edges are useful | Forward entity-link tasks approach 0.95–1.00 | Flat access, same task family | Strong scoped evidence |
| The scaffold helps every CTI task | MLA stays flat/worse; several attribution cells regress | Tasks without the represented relation | **Not supported** |
| It is lifecycle-cheaper | Build: 1.42M tokens / $1.86; incomplete per-arm/update accounting | No matched lifecycle table | **Unproven** |

The 2×2 is the paper's best causal asset, but “tools” remains a bundle: graph, alias/entity state, hybrid indices, typed schemas, descriptions, and result delivery all change together. A flat corpus behind equally ergonomic typed APIs is missing.

The negative MLA boundary is essential. When the task is mostly same-report rewriting and no authoritative edge is materialized, gpt-5.4 is 0.804→0.802 and other models also weaken. The scaffold helps where its represented structure matches the required evidence path.

## Where it fits

`flat chunks/files → explicit operations → materialized relation/entity state → task-native evidence path`

Together with VisDocAgentBench, CTIFoundry reinforces the Interface-resolution claim: **search, resolve, traverse, inspect, collect, and read are different observable operations**, and their value should be tested under a shared output contract.

This refines—not replaces—the existing map. Rich operation surfaces can improve access while still confounding substrate, harness, and controller attribution.

## Open question

The decisive factorial comparison is:

`flat vs materialized corpus state × generic vs typed operation surface × no/generic/task-specific skills`

under the same tool-output schema, prompt placement, model, and total offline+online cost. It must include corpus updates, stale-edge behavior, and an independent non-CTI vertical before the claim becomes durable beyond this setting.
