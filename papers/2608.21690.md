## Research question

Can a long-horizon agent keep history recoverable without forcing every event into its active prompt?

## Research delta

Scroll combines an append-only event log, a persistent Python namespace, and an eviction index. The agent writes queries and aggregations against retained state, then prints only selected evidence into the next prompt. Materialization moves from ingestion time to the moment the question is known.

## Mechanism

`append event → retain lossless state → formulate Python query → aggregate/filter → print selected evidence → answer`

Ingestion uses no LLM call. The cost appears later in model-written query programs and environment execution.

Scroll trails alternatives on some summarization, temporal, and preference-following slices. Weaker backbones collapse on LOCA-256K, making program synthesis capability a binding part of the interface.

## Where it fits

`retain lossless history → query programmatically → materialize only needed context`

This is an early signal for **query-time programmatic context materialization**. It connects State persistence to Evidence materialization, but lacks lifecycle evidence for a durable map edit.

## Open question

Under the same model and reader, how does Scroll compare with indexed retrieval and structured memory when update work, storage, environment CPU, input/output tokens, calls, latency, dollars, and failure recovery are measured end to end?
