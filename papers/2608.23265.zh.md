# EvoWiki: Incremental State Overwriting and Traceable Question Answering for Cross-Meeting Knowledge Evolution

*发表于 2026-08-24 · 迭代推理与验证 · 重要性 4/5 · 已阅读全文 · 置信度：中*

[论文](https://arxiv.org/abs/2608.23265)

> **TL;DR。** EvoWiki 在增量 Build 时物化每个 entity 的 current-valid state，同时保留 superseded version 与 provenance。matched no-overwrite control 的 macro judge accuracy 从 **60.09 降到 51.46**，支持 lifecycle invalidation。完整系统比 top-k RAG 读取更多 evidence，traceability 没有直接评分，build/update 经济性也不完整。

**读图方式。** Build 关闭旧 validity interval 并保持一个 Active state；下方把 matched overwrite 消融与 unmatched complete-Wiki/lifecycle cost 分开。

**不要过度解读。** provenance identifier 属于机制，但 citation correctness 没有评测。

## Problem

系统能否从当前有效状态回答，同时保留审计决策、风险与责任如何变化所需的历史？

## 研究增量

相对 StateMem，最小增量是**增量写入时的 supersession materialization**，而不是回答时才做 value-chain resolution。

## Mechanism

**控制流。** `meeting → resolve/corefer/extract → route update → 关闭旧 validity → append Active → address current/history → answer`

每个 entity-attribute 最多一个 Active value；旧值保留在 version chain 中，带 meeting/span provenance 与 replacement edge。Read 对完整 Wiki 做确定性 entity/time/relation addressing。

## Closest comparison

最近对照是 matched no-overwrite：保持 extraction、coreference、entity Wiki 与 reader 不变，只移除 lifecycle invalidation。

## Decisive evidence

| 主张 | 证据 | 最近控制 | 判断 |
|---|---|---|---|
| overwrite 改善 current-state QA | Full **60.09**，no-overwrite **51.46** | 相同上游结构与 reader | 强内部证据 |
| package 超过 baselines | 两个 reader +9.72/+10.00 macro | 原生 pipeline baselines | 只能归因 package |
| traceability 正确 | 输出 state IDs/provenance，但没评分 | 无 | **未证明** |
| lifecycle 更便宜 | 17,143 Read tokens，114,016 Build/project | Direct/RAG | 不完整权衡 |

LongMemEval 是最强外部证据；MeetingQA/ELITR 相对 full context 仅约一分。很多剩余错误来自 Build extraction/overwrite，确定性 Read 无法找回未写入的 state。

## Field-map consequence

`StateMem answer-time precedence ↔ EvoWiki write-time active-state materialization`

两篇独立工作共同强化 supersession-aware state assembly，但不证明结构化 memory 普遍更优。

## What remains unproven

固定 transcript、extraction、reader、calls、evidence tokens 与 output format，独立改变 answer-time/write-time supersession，并评估 provenance accuracy、更新延迟、存储、break-even queries 与反事实修复。
