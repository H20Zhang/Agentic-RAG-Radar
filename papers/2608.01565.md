## Problem

Complex document QA often requires complementary evidence spread across sections or documents. Flat retrieval repeatedly reconstructs location from semantic similarity, while many GraphRAG systems build useful structure but still traverse it with a fixed policy.

## Core idea

Represent document hierarchy and cross-region relations as a navigable environment, expose operations such as locate / navigate / expand / fetch, and maintain an explicit state of **collected evidence** and **missing evidence**. Retrieval continues until that state indicates the information need is satisfied.

## Agent loop

`Locate → navigate/expand → fetch → update evidence state → identify missing evidence → continue or answer`

## Retrieval design

The retrieval interface is operation-based navigation over document-native structure rather than repeated global top-k search. The evidence state acts as both **progress representation** and a potential **stopping signal**.

## Compared to what

The closest design points are flat passage-level agentic RAG, repeated global semantic search, and GraphRAG systems with fixed traversal/context construction. The research delta is not just better representation; it is exposing that representation as an agent-controllable environment and carrying explicit retrieval progress state.

## Evidence

The abstract reports evaluation across four long- and multi-document QA benchmarks, with average gains of **7.8% in answer quality** and **17.7% in context sufficiency** over the strongest baseline. The radar has not yet checked the full benchmark tables or component ablations, so those gains should not yet be attributed specifically to graph navigation versus evidence state versus extra retrieval budget.

## Why it matters

This is a reusable systems abstraction if it holds up: **data structure should shape the retrieval API**. When hierarchy and cross-region relations already exist in the source, flattening them into chunks and asking an agent to rediscover structure through semantic search may be unnecessary work.

The second important abstraction is explicit evidence state. It gives retrieval a cleaner systems interface than relying on an implicit reasoning trace to remember what has been established and what is missing.

## Limitations / questions

- How much of the gain comes from document structure versus the evidence-state controller?
- How robust is the method when document structure extraction or cross-region relation construction is noisy?
- Are retrieval calls / retrieved tokens matched against the strongest adaptive baselines?
- Does explicit evidence state transfer beyond long-document QA to web, SQL, code, or graph-search agents?

**Curator take:** **4/5**. Potentially important because it co-designs retrieval environment and control state rather than only improving another search policy; confidence remains provisional until full-paper ablations are checked.
