# Rethinking Agentic Search with Pi-Serini: Is Lexical Retrieval Sufficient?

**arXiv:** [2605.10848](https://arxiv.org/abs/2605.10848) · **Published:** 2026-05-11 · **Category:** Evaluation & Analysis · **Importance:** 4/5 · **AI confidence:** Medium

**Code:** https://github.com/justram/pi-serini · **Project:** https://ricky42613.github.io/piserini

**Tags:** `sparse` `documents` `web research` `retrieval depth` `tool use`

> **TL;DR.** Pi-Serini is a baseline correction more than a “BM25 wins” paper: on BrowseComp-Plus, a tuned lexical backend plus deep cached rankings and explicit browse/read tools can outperform released dense-retriever agents, showing that retriever family, ranking depth, and the agent-facing inspection interface must be separated before attributing gains.


## Problem

Agentic-search comparisons often treat the retrieval backend as the main variable. But a shallow/default BM25 baseline can make lexical retrieval look intrinsically weak when the real bottleneck is parameterization, surfaced ranking depth, or the interface the agent uses to inspect that ranking.

## Core idea

Pair a tuned Anserini BM25 backend with a deliberately small retrieval controller. `search` creates a deep cached ranking, `read_search_results` browses deeper ranks without another backend query, and `read_document` inspects selected documents in bounded chunks. This lets the paper distinguish evidence that the backend surfaced from evidence the agent actually previewed or read.

## Agent loop

`form lexical query → cache deep ranking → inspect ranking pages → read selected document chunks → refine/search again or answer`

## Retrieval design

The main systems point is the separation between ranking and interaction. The backend may surface up to a deep candidate set while the controller exposes only a small portion at a time; pagination lets the agent inspect deeper ranks without dumping the entire ranking into model context.

## Compared to what

Released BrowseComp-Plus agents using BM25 or dense retrieval, default versus tuned BM25, and shallow versus deep surfaced rankings.

## Evidence

The paper reports **83.1% answer accuracy** and **94.7% surfaced evidence recall** for Pi-Serini with GPT-5.5 on BrowseComp-Plus. On a 100-query ablation subset, tuning BM25 improves answer accuracy by **18.0 points** and surfaced evidence recall by **11.1 points** over the default configuration; increasing retrieval depth improves surfaced evidence recall by **25.3 points** over shallow retrieval.

The most important negative detail is that **previewed recall saturates much earlier than surfaced recall**. Deep retrieval can place relevant evidence into the cache without causing the agent to inspect it. That makes browsing policy/interface a separate bottleneck from backend recall.

## Why it matters

Pi-Serini weakens two lazy interpretations at once. First, a dense-over-lexical result is not causal if the lexical baseline is poorly tuned or artificially shallow. Second, a high-recall backend is not enough if the agent-facing interface does not let the controller exploit that ranking efficiently.

For this radar, the reusable abstraction is therefore `backend ranking quality × surfaced depth × inspection interface × browsing policy`, not “BM25 versus embeddings.”

## Limitations / questions

- The headline evidence is concentrated on BrowseComp-Plus, so cross-domain generality is not established.
- The strongest tuning/depth ablations are reported on a 100-query subset rather than the full benchmark.
- A frontier model is part of the success condition; the same BM25 backend can perform poorly with weaker search agents.
- Deep surfaced rankings still incur backend work even when the agent never previews most candidates.

**Curator take:** **4/5**. Important because it raises the baseline bar for agentic-search retrieval claims and separates backend recall from agent-visible evidence access; not field-shaping until the result transfers beyond one corpus/benchmark family.
