# CAFE: Self-Improving Search Agents Need Co-Evolving Feedback

*发表于 2026-08-25 · 学习与优化 · 重要性 4/5 · 已阅读全文 · 置信度：中*

[论文](https://arxiv.org/abs/2608.24794)

> **TL;DR。** CAFE 把 corrective feedback 变成 trajectory 内的 learned intervention：agent 学何时请求，shared-parameter critic 随 on-policy failure distribution 一起更新。同一 feedback-SFT + GRPO 家族中达到 **52.5 EM / 60.7 F1**，对照为 **49.7 / 58.0**。但 full package 还改变 request shaping、token credit、critic preference learning 与 online/offline schedule；500 online-step 对照显示 schedule 本身就会显著改变结果。

| 30 秒判断 | |
|---|---|
| **为什么重要** | feedback routing 与 recovery 被放进搜索 policy，而不是固定的 trainer-side critic。 |
| **最强证据** | 同 backbone/checkpoint family：CAFE **52.5/60.7** vs GRPO **49.7/58.0**，并有 component 与 schedule ablation。 |
| **最大限制** | feedback 增加额外 model work，完整 tokens/tools/latency/dollar 没有匹配。 |

## Problem

terminal reward 只能告诉 agent 最后成败，不能在错误扩散前定位并纠正；随着 policy 变强，critic 面对的 failure distribution 也在变。

## Mechanism

`search → optional request_feedback → critic correction → recovery → outcome`

shared Qwen2.5 model 轮流扮演 agent/critic。online RL 用 call-vs-skip success gap shaping feedback request，并重分配 feedback 前后 token advantage；offline RDPO 从 on-policy matched prefixes 学 critic feedback；两者按 iteration 交替。

## Closest comparison

最重要的控制不是异构 leaderboard，而是同一 feedback-SFT family 的 GRPO，以及 matched 500 online steps 的不同 alternation schedules。

## Decisive evidence

| 主张 | 证据 | 最近控制 | 判断 |
|---|---|---|---|
| CAFE package 提升 | **52.5/60.7** vs GRPO **49.7/58.0** | same family | 强内部 package 结果 |
| 相对 reproduced RL baseline | IGPO **50.4/59.4** | authors' checkpoint | 中等增量 |
| shaping 组件各自有用 | CFE-only、advantage-only 都改善，联合最好 | component ablation | 支持两组件 |
| schedule 是实质变量 | 相同 500 online steps，不同切分结果明显不同 | matched steps | 重要混杂因素 |

## What remains unproven

在 matched trajectory state 上随机化 feedback availability，并统一 model/tool calls、total tokens；独立切换 request policy、critic quality 与 alternation schedule。真正应测的是同一 pre-feedback state 下的 recovery probability。

## Field-map consequence

`search policy → feedback-request routing → corrective state → recovery → continued retrieval`

这是 adaptivity placement 的 `early_signal`：policy 可以学“什么时候值得购买一次纠正”。它不等于 co-evolution 这一抽象概念已被独立证明。
