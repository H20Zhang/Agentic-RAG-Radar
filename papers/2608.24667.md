# EviGraph: Towards Verifiable Evidence Construction for Information-Seeking Agents

*Published 25 Aug 2026 · Iterative Reasoning & Verification · Importance 5/5 · Full-text reviewed · Confidence medium*

[Paper](https://arxiv.org/abs/2608.24667)

> **TL;DR.** EviGraph turns retrieved Web content into a span-grounded claim–evidence graph that is both persistent working state and a process-reward surface. On BrowseComp-Plus the clean same-architecture result is **26.9% → 35.9%** when RL is added to the dual-role system. The larger **2.7% → 26.9%** jump also changes interface, verifier mediation, search persistence, and stopping, so it is package evidence rather than a graph-memory effect.

## Research question

Can an information-seeking agent represent *which span supports which claim under which constraint* as explicit state, rather than leaving grounding implicit in a growing search trace?

## Research delta

The narrower delta is not “graphs help search.” It is:

`raw retrieval → frozen span verification → policy-proposed claim/evidence write → structural commit → support/conflict/MISSING state → next search or stop`

This turns evidence recording into a separately trainable and auditable transition.

## Mechanism

The executor sees the question, constraints, graph snapshot, query log, and remaining budget, but not raw pages. A frozen verifier inspects search results/pages and returns source-linked verbatim spans with constraint tags and support/conflict polarity. The shared policy, in an evidence-proposal role, maps those items to `Add` or `Support` requests. A deterministic validator checks source identity, exact-item matching, duplicate signatures, and graph invariants; it does **not** decide semantic entailment or when to stop.

The committed graph exposes positive support, conflicts, and unresolved constraints. Search rewards combine retrieval novelty with graph-coverage potential; evidence-writing rewards credit structurally accepted first evidence and graph-quality potential.

## Evidence & attribution

| Claim | Evidence | Closest control | Assessment |
|---|---|---|---|
| Process RL improves the same dual-role system | **26.9% → 35.9%** BrowseComp-Plus accuracy | Dual-role, no RL | Best causal result |
| Architecture changes behavior strongly | **2.7% → 26.9%** before RL | Monolithic agent | Package-level only |
| Gain is not just more search | Search count is essentially unchanged in the matched RL comparison while generated tokens fall | Same dual-role architecture | Supports process-objective effect |
| Generalizes beyond one benchmark | Gains reported on BrowseComp, GAIA, XBench; LiveVQA transfer is competitive | Cross-benchmark transfer | Directional, not mechanism isolation |

Generated-token accounting includes policy/verifier text but excludes environment-supplied page text; page visits are verifier actions rather than executor search calls. That makes the paper more careful than many search-agent reports, but lifecycle cost is still incomplete.

## Where it fits

`retrieval → evidence materialization → persistent support/conflict state → continue / redirect / stop`

This is an `early_signal`: a strong representation/control design point, not yet evidence that claim graphs are generally superior to matched non-graph state.

## Open question

Hold raw search results, verifier outputs, answer model, stopping budget, and total tokens/calls fixed. Then compare linear verified evidence, typed tables, and the claim graph while independently toggling process reward. That would isolate representation from privileged verification and RL.
