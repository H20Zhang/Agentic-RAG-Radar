## Problem

当前 reasoning gap 需要 KG facts、reusable templates、两者还是都不需要？

## Mechanism

`encode gap → choose none/KG/template/both → retrieve → develop answer → critique → update state/template → stop`

## Closest comparison

最干净的对照固定 Manager、Dev、Critic、retriever、model 与 budget，只把 learned Proxy 换成 always-none/KG/template/both。STELLA/Biomni 的 end-to-end 对比不具同等归因力。

## Decisive evidence

Learned vs always-both 为 16.52/11.73 vs 13.18/9.02；GRPO vs SFT 仅 16.52 vs 15.08、11.73 vs 10.62。Oracle both 只到 18.06/13.05，说明 routing headroom 有限。

## What remains unproven

Full-system gain 混合 structured state、512 templates、commercial Manager/Dev/Critic 与 triplet retrieval。HLE audit 中 wrong Proxy 仅占 13.1%；82.4K data-construction rollouts 的 API 成本也未与 training table 完整对齐。

## Field-map consequence

这是 **structured-gap dual-source routing** 的 early signal，不构成 self-evolving agent 的稳定方向。
