# S2G-RAG: Structured Sufficiency and Gap Judging for Iterative Retrieval-Augmented QA

**Paper:** [ACL 2026](https://aclanthology.org/2026.acl-long.1185/) · **arXiv:** [2604.23783](https://arxiv.org/abs/2604.23783) · **Published:** 2026-04-26 · **Category:** Iterative Reasoning & Verification · **Importance:** 4/5 · **AI confidence:** High

**Tags:** `iterative search` `evidence state` `gap prediction` `stopping` `multi-hop QA` `compression`

> **TL;DR.** S2G-RAG makes retrieval progress explicit: a lightweight judge first asks whether accumulated evidence is sufficient and, if not, emits structured missing-information items that become the next retrieval query.

## Problem

Multi-turn RAG can fail in two opposite ways: stop on an incomplete evidence chain, or keep accumulating redundant/distracting text. Conditioning the next search on a raw reasoning trace does not give the controller a clean state variable for either failure.

## Core idea

Maintain a compact sentence-level Evidence Context and introduce **S2G-Judge**, which outputs either `sufficient` or structured gap items describing what information is still missing. The system deterministically maps those gaps into the next retrieval query.

## Agent loop

`evidence memory → sufficiency judgment → gap items if needed → next query → retrieve/extract → update evidence → repeat or answer`

## Retrieval design

The controller is a LoRA-tuned Llama-3.2-3B model distilled from GPT-4o-mini trajectories. The main experiments cap retrieval at four turns and top-6 documents per turn; they evaluate both BM25 and E5 while keeping the answer reasoner fixed at Llama-3-8B.

## Compared to what

The closest design points are SIM-RAG and RAG-Critic, plus IR-CoT, FLARE, Self-RAG, and standard RAG. The important delta is not merely iteration: it is an explicit **sufficiency + missing-information state** that controls the next query.

## Evidence

Under BM25, S2G-RAG reports **43.3/56.5 EM/F1 on HotpotQA**, versus **32.7/43.3** for SIM-RAG, and **41.7/48.6 on 2Wiki**, versus **34.1/40.2**. The key ablation is unusually useful: removing S2G-Judge drops HotpotQA by **15.8 EM / 19.0 F1** while the retriever, maximum turns, per-turn top-k, and answer reasoner remain fixed.

The sentence-level Evidence Extractor is also not cosmetic: against full-text accumulation in the same pipeline, the paper reports a **17.7% latency reduction** together with +3.8 EM / +4.0 F1.

## Why it matters

This corrects the chronology of the radar's current evidence-state story. Explicit collected/missing-information control was already a concrete, strongly ablated design point before the August DocNavRAG work. DocNavRAG may still add value through a document-native navigation environment, but **explicit missing-evidence state is not its unique novelty**.

## Limitations / questions

- The main experiments fix per-turn retrieval depth, so this is not yet a full resource-allocation controller.
- The method combines a trained judge with an Evidence Extractor; the cleanest causal claim is about the structured control interface plus these components, not a single scalar state alone.
- The evidence is strong on benchmark QA but not yet on web, SQL, code, or multimodal information seeking.

**Curator take:** **4/5**. Important because it gives explicit evidence state a stronger and earlier baseline, with a matched-budget controller ablation rather than only an end-to-end score.
