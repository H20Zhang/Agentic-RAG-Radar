# Risk-Aware Reranking for Agentic Tool Retrieval

*发表于 2026-08-24 · 检索与工具使用 · 重要性 4/5 · 已阅读全文 · 置信度：中*

[论文](https://arxiv.org/abs/2608.22751) · [代码](https://github.com/qli447/risk-aware-tool-retrieval-release) · [CIKM](https://doi.org/10.1145/3799682.3840706)

> **TL;DR。** 这篇论文把检索到的 tool shortlist 明确为执行前的风险暴露面。最干净的消融只在相同冻结表征与 relevance head 上加入 risk head：RVR@5 从 0.188 降至 0.138，NDCG@5 从 0.558 变为 0.551。它证明的是“标签风险暴露—相关性”的可调权衡，不是 agent 实际执行更安全。

## Problem

在 agent 行动之前，工具检索能否保留有用候选，同时减少不必要的高风险动作暴露？

## 研究增量

最小增量是 **retrieval-time risk-aware tool exposure**。方法分别预测 query-conditioned relevance 与 tool-level risk，再用推理时系数合成；审计过的 registry 还可增加确定性风险与权限上限。

## Mechanism

**控制流。** `query → relevance/risk scoring → 调整 λ → 可选 graph/rules → 暴露 top-k → agent 选择`

核心 risk 是工具级别的，无法看到调用参数、用户权限或运行环境。Rule mode 直接消费审计标签，属于更强的部署条件。

## Closest comparison

最近的因果对照是相同 frozen representations 与 relevance head，只切换 learned risk head；通用 reranker 的 top-100 与 full-pool 主表只作系统背景。

## Decisive evidence

| 主张 | 证据 | 最近控制 | 判断 |
|---|---|---|---|
| learned risk 降低标签暴露 | NDCG/RVR/SRR **0.558/0.188/0.097 → 0.551/0.138/0.063** | 相同冻结表征与 relevance head | 强组件证据 |
| 硬过滤更保守 | RVR/SRR 降到 **0.073/0.019** | 同一系统加审计规则 | 成立，但依赖元数据 |
| 保留必需高风险工具 | NeedRisk-Hit **0.660 → 0.397** | 同一 benchmark | **不成立** |
| agent 更安全 | 只有候选分析，没有执行结果 | 无 | **未证明** |

主表不是因果中心：通用 reranker 只看 top-100，而完整方法扫描 full pool。Graph smoothing 在组件消融里也没有改善风险指标。

## Field-map consequence

`capability retrieval → candidate-action exposure → execution guardrails`

这是 Retrieval & Tool Use 的单篇 early signal；它与 ToolScout 的 candidate coverage 审计互补，但 coverage 与 exposure risk 是不同故障面。

## What remains unproven

在相同 candidate set、权限、retrieval latency、scoring cost 与调用预算下，独立改变 risk objective、rule metadata 与 executor，并同时测 task success 与实际 harm。
