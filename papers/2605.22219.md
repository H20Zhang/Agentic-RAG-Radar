# SGR-Bench: Benchmarking Search Agents on State-Gated Retrieval

**arXiv:** [2605.22219](https://arxiv.org/abs/2605.22219) · **Published:** 2026-05-21 · **Category:** Evaluation & Analysis · **Importance:** 4/5 · **AI confidence:** High

**Dataset:** https://huggingface.co/datasets/PKUAIWeb/SGR-BENCH

**Tags:** `web` `state-gated retrieval` `filters` `structured outputs` `evaluation`

> **TL;DR.** SGR-Bench isolates a retrieval failure that open-web benchmarks often blur: an agent can find the right specialized website yet still fail because answer-bearing evidence is hidden behind the wrong site-specific filters, views, hierarchy, scope, or time window. The environment's retrieval state is therefore a separate control variable from source discovery and from the agent's internal evidence state.

## Problem

Search-agent benchmarks mostly stress source discovery, browsing depth, cross-page aggregation, or generic web-action execution. Specialized data sites introduce another failure surface: relevant evidence may remain invisible until the website is configured into the correct retrieval state.

## Core idea

Define **state-gated retrieval (SGR)** as information seeking where answer-bearing evidence appears only after the agent establishes the right site-specific retrieval state. SGR-Bench contains 100 expert-curated tasks across 12 public data ecosystems and six source families, with paired goal-oriented and constraint-guided variants of the same underlying information need.

## Agent loop

`discover source → infer required site state → set filter/view/hierarchy/scope → inspect exposed evidence → update state → continue or answer`

## Retrieval design

The benchmark separates source discovery from evidence exposure. A task may require multiple dependent state changes; evidence exposed under one state can determine the next filter, scope, or branch. The paired prompt variants make some retrieval logic explicit in one condition and implicit in the other while keeping source and answer fixed.

## Compared to what

BrowseComp/WebWalker/WideSearch-style search benchmarks centered on source discovery and traversal, plus WebArena/Mind2Web/WorkArena-style browser benchmarks centered on action grounding and task execution rather than specialized retrieval-state establishment.

## Evidence

The strongest evaluated system reaches **66.18% item-level F1** while row-level correctness remains materially lower. A manual audit of **156 analyzable failed CLI trajectories** finds that **retrieval-scope drift (37.2%)** and **criterion mismatch (27.6%)** dominate, while final answer composition accounts for **10.3%**.

That error profile is the important result: many failures happen after the agent has already reached a relevant source. The missing capability is preserving the source-specific retrieval state under which the right evidence remains visible and valid.

## Why it matters

SGR-Bench adds an environment-state axis that is easy to conflate with retrieval quality or internal memory. A search agent may have a good plan, a strong web search engine, and adequate reasoning, yet still fail because it operates the right data source in the wrong state.

For Agentic RAG, this suggests a sharper decomposition: `source discovery × environment retrieval state × evidence state × policy`. Internal evidence tracking cannot substitute for correctly configuring an external data system.

## Limitations / questions

- The benchmark has 100 tasks and is concentrated on specialized public data-retrieval websites; broader workload coverage is still needed.
- The reported CLI results are system-level outcomes because model and CLI/harness choices differ across systems; they should not be read as pure model rankings.
- Retrieval-state errors may depend heavily on website UI stability and source-specific interaction affordances.
- The benchmark diagnoses the failure but does not identify which controller/state representation best repairs it.

**Curator take:** **4/5**. Important because it adds a concrete, measurable environment-state failure mode missing from many search benchmarks; not yet field-shaping because the benchmark is still small and does not provide intervention-style causal repairs.
