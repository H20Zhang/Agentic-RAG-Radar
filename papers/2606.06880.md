# Towards Retrieving Interaction Spaces for Agentic Search

**arXiv:** [2606.06880](https://arxiv.org/abs/2606.06880) · **Published:** 2026-06-05 · **Category:** Retrieval & Tool Use · **Importance:** 4/5 · **AI confidence:** High

> **TL;DR.** RISE resolves the first-order DCI scaling tension by redefining retrieval as **construction of a bounded interaction space**, not final snippet selection. The agent still gets shell-style evidence operations, but only inside a persistent retrieved workspace.

## Problem

Snippet/top-k retrieval scales but compresses what the agent can inspect. Raw DCI preserves fine-grained operations but broad shell commands scan the whole corpus, becoming slow and noisy as distractors grow.

## Core idea

Use BM25 to import a persistent candidate set into a per-query workspace outside the model's context window. The agent can repeatedly grep/read that space. Full RISE also preprocesses documents with line-numbered table-of-contents anchors so shell operations can land on relevant spans without full-file scans.

## Agent loop

`subquery → retrieve/import candidates → shell-search workspace → targeted read/verify → import more if needed → answer`

## Compared to what

The key triangle is conventional snippet retrieval, raw full-corpus DCI, and RISE's bounded workspace. RISE-BM25 removes the document-processing layer and isolates the value of the boundary itself.

## Evidence

On the 100-query BrowseComp-Plus sample, RISE with gpt-5.4-mini matches raw DCI at **78% accuracy** while reducing per-query cost from roughly **$1.10 to $0.28**. Removing document processing costs **1–4 points** across model tiers at 100K scale. At 1M documents RISE-BM25 remains operationally stable while raw DCI suffers substantial wall-clock failures, though that headline comparison uses different model tiers.

## Why it matters

The paper turns “retrieval versus direct interaction” into a composition: **retrieval supplies a scalable boundary; interaction supplies resolution inside it**. That is a more durable abstraction than either extreme.

## Limitations / questions

- Full RISE was not run at 1M because the extra 900K documents were not passed through the TOC preprocessing pipeline.
- The proof of concept uses BM25 plus one-time LLM document structuring; alternative boundary/navigation mechanisms remain open.
- Some scale comparisons are not fully model-matched.

**Curator take:** **4/5.** A key bridge from raw DCI to scalable agent workspaces; the important idea is retrieval as environment construction rather than prompt stuffing.
