# A New Role for Relevance: Guiding Corpus Interaction in Agentic Search

**arXiv:** [2607.24223](https://arxiv.org/abs/2607.24223) · **Published:** 2026-07-27 · **Category:** Retrieval & Tool Use · **Importance:** 4/5 · **AI confidence:** High

> **TL;DR.** RARG keeps relevance alive **inside** direct corpus interaction: relevance does not merely choose a workspace; it orders traversal, initializes likely entry points, and prioritizes local grep matches under a finite observation budget.

## Problem

Raw DCI treats files and lexical matches too uniformly. RISE/DR-DCI use relevance to bound or expand a workspace, but local interaction can still spend time on weak files/matches once that space exists.

## Core idea

Use document-level relevance as a traversal order, inject query-relevant paragraphs as entry points, and optionally rerank a wider pool of grep matches so informative local evidence reaches the model before truncation hides it.

## Agent loop

`recall/rank → traverse scoped documents → grep locally → prioritize matches → inspect/verify → answer`

## Retrieval design

Retrieval scores remain active during interaction rather than only selecting the workspace boundary; relevance controls which local operations and observations get scarce execution/attention budget.

## Compared to what

The paper directly compares with RISE, RISE-BM25, raw DCI, embedding retrieval agents, and a NeMo retrieval-oriented agent.

## Evidence

On the 100-query BrowseComp-Plus setup with GPT-5.4-mini, **RARG++ reaches 84%** accuracy with **23.9 tool calls**, versus **78% / 28.7** for RISE and **78% / 99.1** for DCI. At 1M documents RARG++ reports **79%** versus **69%** for RISE-BM25. A useful negative result is the generative reranking variant: it converges faster at **17.8 tools** but drops to **75% accuracy**, showing that lower interaction count is not automatically a better search policy.

## Why it matters

The DCI lineage arrives at a more nuanced conclusion than “remove ranking”: **relevance is useful as an execution prior when it guides interaction without becoming a fixed evidence bottleneck**.

## Limitations / questions

- Performance depends on embedding quality at both document and local-match granularity.
- Order-preserving grep and reranking add search latency; tool-count gains are not identical to wall-clock gains.
- Evidence is concentrated on BrowseComp-Plus, four BRIGHT subsets, and GPT-5.x backbones.

**Curator take:** **4/5.** Important because it closes the false dichotomy between semantic retrieval and direct interaction: relevance can guide the execution of a high-resolution interface instead of replacing it.
