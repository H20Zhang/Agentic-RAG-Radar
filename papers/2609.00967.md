# CoBRA: Learning Tool-Use Boundaries via Counterfactual Margins

*Published 2026-09-01 · Learning & Optimization · Importance 4/5 · Full text reviewed · Confidence: medium*

[Paper](https://arxiv.org/abs/2609.00967)

> **TL;DR.** CoBRA reframes selective retrieval as a **same-query marginal-utility decision** rather than a difficulty or uncertainty heuristic. Its cleanest mechanism is MARS-RL: internal and retrieval-forced rollouts share the system prompt, tool schema, and reference policy, then the branch reward gap enters the policy advantage. That is stronger route-level supervision, but it is still not a budget-matched causal estimate of “retrieval content alone.”

| 30-second verdict | |

| **Biggest caveat** | The discovery margins come from two separately fine-tuned experts, while the MARS ablations change realized tool-call rates; token, latency, retrieved-byte, and dollar budgets are not matched. |

## Research question

For a particular query, is external retrieval worth its cost **relative to answering from the same model's internal knowledge**, and can that marginal value become the learning signal for routing?

## Mechanism

CoBRA uses Qwen3-4B with a Wikipedia search tool. Counterfactual Boundary Discovery first creates an internal expert trained on successful no-tool traces and an external expert trained on successful retrieval traces. Running both on the same large query pool yields a utility margin `external − internal`, where utility is judged exact match minus `0.10 × #Tool`. Clear internal-favored and external-favored cases train a warm router. MARS-RL then revisits boundary-heavy cases: for each query, reference-split rollouts suppress the first tool action on one branch and prefix a tool call on the other, while keeping the system prompt, tool schema, and reference policy shared. Per-branch normalization plus a symmetric branch-margin term injects the route difference into policy advantage.

## Research delta

The closest conceptual predecessors are selective-retrieval routers such as SKR and outcome-trained search agents. Their trigger can correlate with uncertainty, complexity, or final reward without directly estimating **whether this query benefits from retrieval**. CoBRA changes the optimization object from an absolute trigger score to a paired internal-versus-external utility margin. The important comparison is therefore not its heterogeneous headline leaderboard, but whether the route intervention survives matched-policy ablations.

## Resource accounting

The online metric prices only search-call count: `Util = jEM − 0.10 × #Tool`. That is a useful explicit trade-off, not a complete operating-cost model. The offline pipeline is substantial: two expert SFTs take about **4 GPU-hours each**, paired counterfactual generation about **35 GPU-hours**, warm-router SFT about **4 GPU-hours**, and one MARS-RL run about **100 GPU-hours** on the reported H20 setup; S2 alone generates **777,404** paired rollouts. Retrieval uses top-3 passages and up to four tool turns. Token, wall-clock, API-dollar, and evidence-volume matching are still absent from the main comparisons.

## What remains unproven

The first “counterfactual” partition is not a pure do-intervention: the internal and external experts were trained on different rejection-sampled success traces, so their margin contains both route value and branch competence. MARS-RL fixes much of the interface problem by branching the same reference policy, but its ablations still produce different call counts. A stronger experiment would fix one policy checkpoint, force internal/external branches on a pre-specified query population, match retrieval result volume and realized token/latency budgets, then randomize returned evidence or its visibility to separate **invocation value** from **evidence value**.

## Where it fits

`query → internal/external route intervention → evidence acquisition → answer → route-level marginal credit`.

`early_signal`: **counterfactual retrieval routing** is a promising adaptivity coordinate, but one Qwen3/Wikipedia study does not change the durable Field Map.
