# CoBRA: Learning Tool-Use Boundaries via Counterfactual Margins

*发表于 2026-09-01 · 学习与优化 · 重要性 4/5 · 已阅读全文 · 置信度：中*

[论文](https://arxiv.org/abs/2609.00967)

> **TL;DR。** CoBRA 把选择性检索从“这个问题看起来难不难”改写成**同一查询上调用外部检索的边际效用**。其中最干净的设计是 MARS-RL：内部作答分支与强制检索分支共享 system prompt、工具 schema 和 reference policy，再把两个分支的奖励差写进 policy advantage。它强化了路由层监督，但仍不能当成“检索内容本身”的等预算因果效应。

| 30 秒判断 | |
|---|---|
| **为什么重要** | 它把“要不要检索”变成显式干预对象：在同一查询上比较内部作答与外部检索，而不是比较两组由策略自己挑出来的任务。 |
| **最强证据** | 在相同 warm initialization 下，完整 MARS 的 **Avg jEM=0.5418**；去掉 reference-split rollout 后为 **0.5066**，去掉 per-branch normalization 为 **0.4866**，去掉 branch-margin term 为 **0.4817**。 |
| **最大限制** | 初始 margin 来自两个分别微调的 expert；MARS 消融又改变了实际工具调用量，因此 token、延迟、证据量和美元成本仍未配平。 |

## Problem

对某个具体查询，外部检索相对于同一模型依赖内部知识作答，究竟值不值得付出成本？这个**边际价值**能否直接成为检索路由的学习信号？

## Mechanism

CoBRA 以 Qwen3-4B 和 Wikipedia 搜索工具为主体。Counterfactual Boundary Discovery 先分别训练 internal expert 与 external expert：前者只保留成功的无工具轨迹，后者只保留成功的检索轨迹。两者在同一大规模查询池上运行，得到 `external − internal` 的效用差，其中效用定义为 judged exact match 减去 `0.10 × #Tool`。清晰的 internal-favored / external-favored 样本用于训练 warm router。随后 MARS-RL 专门处理边界样本：同一查询从相同 reference policy 分成两条 rollout，一条在第一步禁止工具调用，另一条预置 tool call；system prompt 与工具 schema 保持一致。再通过分支内归一化和对称 branch-margin term，把路由差异写入策略优势。

## Closest comparison

最近的比较对象是 SKR 一类选择性检索路由器和依赖最终结果奖励训练的 search agent。它们可以根据不确定性、复杂度或最终 reward 学到触发规则，却不直接估计**这个查询是否因为检索而受益**。CoBRA 真正改变的是优化对象：从绝对触发分数变成同查询的 internal-versus-external utility margin。因此最重要的证据不是异构 leaderboard 的 headline，而是 route intervention 在 matched-policy 消融中是否成立。

## Cost

在线指标只给搜索调用次数定价：`Util = jEM − 0.10 × #Tool`。这比只报准确率更好，但仍不是完整成本。离线训练相当重：两个 expert SFT 各约 **4 GPU-hours**，paired counterfactual generation 约 **35 GPU-hours**，warm-router SFT 约 **4 GPU-hours**，单次 MARS-RL 约 **100 GPU-hours**；S2 本身生成 **777,404** 条 paired rollouts。检索每次返回 top-3 passage，每条 trajectory 最多四个 tool turn。主实验仍缺 token、wall-clock、API 美元成本与 evidence volume 的匹配。

## What remains unproven

第一阶段所谓“counterfactual”不是纯粹的 do-intervention：internal 与 external expert 分别由不同的成功轨迹做 rejection-sampling SFT，因此 margin 同时包含**路由价值**与**分支策略能力**。MARS-RL 用同一 reference policy 分支，解决了大部分接口混杂，但各消融的实际调用次数仍不同。下一步更强的实验应固定同一 policy checkpoint，在预先确定的查询总体上强制 internal/external route，配平返回证据量与实际 token/latency，再分别随机化 returned evidence 和 visibility，才能拆出 **invocation value** 与 **evidence value**。

## Field-map consequence

`查询 → internal/external 路由干预 → 证据获取 → 作答 → 路由层边际 credit`。

这是 `early_signal`：**counterfactual retrieval routing** 是值得单独研究的 adaptivity coordinate；单篇 Qwen3/Wikipedia 工作不改 durable Field Map。
