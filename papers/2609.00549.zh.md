# Skill Following: Evaluating Actual Skill Use in Retrieval-Enabled LLM Agents

*发表于 2026-09-01 · 评测与分析 · 重要性 4/5 · 已阅读全文 · 置信度：中*

[论文](https://arxiv.org/abs/2609.00549)

> **TL;DR。** 这篇工作暴露的是一个评测对象混淆：**“Agent 选择了检索”与“检索到的内容确实改善了这个任务”不是同一个量**。Gemini-2.5-Flash-lite 在三个 MBPP+ 数据切分上，传统 aggregate lift 为正，但同任务配对的 RAE 为负。这支持拆分评测对象，而不能据此断言“检索有害”。

| 30 秒判断 | |
|---|---|
| **为什么重要** | 它把“Agent 在看起来更容易成功的任务上选择了检索”改写为同任务问题：真正发生检索后，这条检索到作答链路是否有帮助？ |
| **最强证据** | Gemini-2.5-Flash-lite 的 aggregate lift / RAE 在三个 MBPP+ 数据切分上分别为 **+6.2/-15.6**、**+16.2/-15.9**、**+4.4/-22.2**；HumanEval+ 为 **-0.1/-21.1**。 |
| **最大限制** | RAE 条件化在 skill-enabled policy 自己选择的 post-treatment 子集上；paired disabled run 还移除了检索工具，因此不是纯粹的内容干预。 |

## Problem

当检索是可选动作时，表面增益究竟来自 **Agent 选择在哪些任务上检索**，还是来自检索证据真正改变了这些同一任务的结果？传统 retrieved-vs-skipped 聚合比较把两者混在一起。

## Mechanism

skill-enabled Agent 可以调用 `search_skills`；BM25 在小型程序化 skill 库中检索 top-3，并把完整 skill 文本加入上下文，每个任务最多三次调用。skill-disabled 对照移除该工具。评测在相同任务、模型、解码与 seed 上做配对，然后区分三个对象：skill-enabled 内部的传统 retrieved-vs-skipped aggregate lift、所有配对任务上的 OAE，以及只在 skill-enabled 实际调用检索的任务子集上计算的 RAE。

## Closest comparison

最近的对照不是另一个检索算法，而是**传统 aggregate comparison 本身**。它比较两个由 policy 自主选择出来的不同任务子集，因此可能把“触发器会挑任务”误记成“检索内容有用”。OAE 在全体同任务配对上消除任务组成差异；RAE 再聚焦到实际发生检索的调用。

## Decisive evidence

| 主张 | 证据 | 最近控制 | 判断 |
|---|---|---|---|
| aggregate 结论会在同任务配对后翻转 | Gemini 三个 MBPP+ 数据切分的 aggregate/RAE：**+6.2/-15.6**、**+16.2/-15.9**、**+4.4/-22.2** | 同模型、同任务切分 | selection 与 actual-use 是不同评测对象 |
| 不是单一数据切分现象 | 同模型 HumanEval+ 为 **-0.1/-21.1** | 同一 paired protocol | 差异不只出现在一个 MBPP+ split |
| 不能把机制简单归给 skill 内容 | Gemini pooled RAE：Normal **-17.9**、Filler **-5.0**、Random **-15.4**、Corrupted **-17.2** | 改变返回内容 | 工具接口与内容利用仍纠缠 |
| “是否遵循 skill”细粒度标签证据较弱 | 五分类人工一致性 α **0.377**；二分类 engaged/not-engaged 一致率 **84%** | 独立人工/GPT 审计 | outcome pairing 比语义 adherence 标签更稳 |

## What remains unproven

RAE 仍然条件化在 skill-enabled 执行自己选出的 **post-treatment retrieval subset**，因此不是针对预处理总体的无偏平均因果效应；skill-enabled 与 skill-disabled 还存在工具可用性差异。更强的因果实验应固定接口，分别随机或强制控制 invocation、returned content 与 content visibility，并完整报告 token、工具调用、延迟与美元成本。

## Field-map consequence

`retrieval policy → retrieval invocation → returned skill → context uptake → same-task outcome`。

这是 `early_signal`：**retrieval-invoked actual use** 是值得单独测量的评测坐标；单篇程序化 skill 研究不改 durable Field Map。
