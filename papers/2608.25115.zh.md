# Less can be More: Relieving RAG Bottlenecks via Evidence Frontloading and Pressure-Adaptive Budgeting

*发表于 2026-08-25 · 检索与工具使用 · 重要性 4/5 · 已阅读全文 · 置信度：中*

[论文](https://arxiv.org/abs/2608.25115)

> **TL;DR.** PACE 把两个问题拆开：固定 candidate pool 内先做 evidence frontloading，再根据 reranker/LLM 的实时 serving pressure 调整 reranking depth。论文支持的是“evidence ordering + runtime budget control”两因素结果，而不是笼统的“adaptive RAG 更好”。

| 30 秒判断 | |
|---|---|
| **为什么重要** | system pressure 本身成为 retrieval-budget signal；“证据够不够密”和“买多少 reranking compute”可以分开测。 |

## Problem

RAG 的瓶颈会随 workload 移动：arrival rate 或 reranking budget 上升时，reranker 可能先于 LLM 成为瓶颈。直接缩小 `D` 虽然降 compute，却可能把 multi-hop supporting evidence 一并裁掉。

## Mechanism

`fixed retrieval pool → evidence-frontloading reorder → pressure-conditioned D(q) → rerank → top-5 context → answer`

frontloading 用 query relevance、complementarity 与 soft chain anchors 构造 monotone-submodular marginal coverage objective；budget controller 则看 reranker 与 LLM 的相对 queue/service pressure，在 `Dmin...Dmax` 中调整本次 reranking 数量。它不发起额外 retrieval，也不扩大 corpus boundary。

## Closest comparison

最重要的比较有两类：固定 `D` 下比较不同 reordering，隔离 evidence ordering；online serving 中对所有 reordering method 使用同一 pressure-adaptive budget policy，让 selected `D` 与 latency 尽量可比，再看 evidence recall 差异。

## Decisive evidence

| 主张 | 证据 | 最近控制 | 判断 |
|---|---|---|---|
| 小 budget 下 frontloading 保留更多完整证据 | HotpotQA `D=100` standard **41.13** vs PACE `D=50` **62.38**；2Wiki **48.76 vs 54.39** | fixed-budget controls | 强 |
| pressure-aware D 能缓解 reranker queueing | QPS 上升时减小 `D`、p95 latency 更稳定 | fixed `D=100` | 直接但 system-specific |
| recall 增益不是因为 adaptive method 获得更大 budget | online 对 reordering methods 使用 same adaptive-budget policy | matched budget controller | 有用的因子隔离 |
| “less can be more”体现在 final evidence top-5 | QPS=1.8 约半 budget、R@5 高约 20% | fixed full budget | 证据质量，不是 answer correctness |

## What remains unproven

需要真正的 `frontloading on/off × adaptive D on/off` factorial，在同一 retriever、candidate pool、reranker、generator、hardware 和 arrival trace 下，同时报 answer accuracy、evidence recall、p95 latency、实际 reranked pairs 与 GPU-seconds。否则 semantic ordering gain 与 queue-control gain 仍可能在 end-to-end claim 中重新混在一起。

## Field-map consequence

`resource accounting → serving-pressure-aware retrieval budget → evidence materialization`

这是 `early_signal`：runtime systems state 值得进入 adaptivity surface；当前证据还没有证明 queue-pressure policy 自身提高了 semantic correctness。
