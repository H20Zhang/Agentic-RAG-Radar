# DR-DCI: Scaling Direct Corpus Interaction via Dynamic Workspace Expansion

**arXiv:** [2606.14885](https://arxiv.org/abs/2606.14885) · **Published:** 2026-06-12 · **Category:** Retrieval & Tool Use · **Importance:** 4/5 · **AI confidence:** High

> **TL;DR.** DR-DCI turns retrieval into an **agent-callable workspace expansion action**: global retrieval pulls candidates into persistent state; DCI then searches, compares, and verifies evidence locally inside that workspace.

## Problem

Raw DCI has the right local evidence operations but the wrong scaling boundary: every broad search can hit the full corpus. A one-shot retriever scales, but fixes the evidence set before later constraints emerge.

## Core idea

Maintain a persistent workspace `W_t`. At any turn the agent can call `pull(query, k)` to add ranked documents, operate on all materialized evidence with terminal tools, or finalize. Retrieval and DCI receive different jobs: corpus-scale discovery versus workspace-scale resolution.

## Agent loop

`reason → pull(query,k) → inspect/compare workspace with DCI → refine constraint → pull again or verify → answer`

## Retrieval design

Retrieval performs corpus-level candidate discovery; DCI performs workspace-level search, comparison, and span verification. A ranked preview guides attention without becoming the canonical evidence interface.

## Compared to what

The strongest controlled comparison is Raw-DCI under the same DCI-style tool environment. The paper also uses a single-pull static workspace and BM25 search-only baselines, plus external reference systems.

## Evidence

On the full **830-query BrowseComp-Plus** evaluation, DR-DCI reports **71.20%** accuracy versus **62.90%** for Raw-DCI while reducing average tool calls **37.53 → 30.94**, wall time **3139.10s → 146.16s**, and estimated total cost **$88.13 → $34.91**. Optional workspace-preserving context reset reaches **73.25%**. The interface remains effective through controlled 100K–10M corpus scaling and transfers to a 20M-document Wiki-18 setup.

## Why it matters

This makes retrieved documents **durable environment state** rather than transient prompt context. Retrieval becomes a control action that changes what future shell/search operations can see.

## Limitations / questions

- The system bundles dynamic pull, workspace materialization, ranked previews, terminal-aware harness details, and optional reset.
- External systems are not fully controlled comparisons; the Raw-DCI and interface ablations carry the strongest causal weight.
- Large-scale validation still uses static file-per-document corpora rather than mutable web/API sources.

**Curator take:** **4/5.** A strong systems realization of the bounded-interaction idea because it makes the boundary dynamic and measures accuracy, tools, wall time, and cost together.
