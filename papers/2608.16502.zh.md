# ToolScout：固定工具库也会发生 Source-Style Collapse

**中文** | [English](2608.16502.md) · [返回首页](../README.md) · [Research Library](../library/README.md)

[Paper](https://arxiv.org/abs/2608.16502) · **Importance: 3/5**

> **Research delta.** ToolScout 发现：tool registry 没变，不代表 capability retrieval 没有 distribution shift。一个对单一来源微调的 specialist，可以在其他来源生成的 query-tool pairs 上失去几乎全部 gold-tool coverage；系统因此需要 compatibility guard，而不是盲信 specialist。

## Problem

Agent 规划前通常只看到 top-k tool/skill cards。如果正确 capability 没进入候选集，后续 reranker、planner 与 executor 都无法修复。

这里的“source style”不只是措辞，还包括 query verbosity、schema-reference pattern，以及 query 与 target tool 的配对惯例。因此 fixed corpus 仍然可能出现 retrieval transfer failure。

## Mechanism

`query batch/window → TF-IDF compatibility → safe: specialist / unsafe: aggregate retriever → top-20 → rerank → optional few-shot repair`

ToolScout 在 calibrated safe band 内保留 specialist；检测到 mismatch 后切换到 aggregate-trained checkpoint；有 matched examples 后再继续微调 specialist。

## Closest comparison

最接近的对照不是另一个 planner，而是固定 aggregate retriever：它在混合来源上已经达到 85.2%，只比 routed 方案的 86.1% 略低。这个对照把主要结论限定为 source-style collapse 的诊断，而不是 routing architecture 的显著端到端优势。

## Decisive evidence

| Claim | Evidence | Closest control | 判断 |
|---|---|---|---|
| Source-specific adaptation 会 collapse | **91.8% matched →22.3% mixed coverage** | 同一 checkpoint、固定 registry | ToolRet 内强证据 |
| Compatibility switch 能恢复 coverage | **22.3% →86.1%** | fixed aggregate 已有 85.2% | 支持，但 routing margin 小 |
| 原始 API schema 是原因 | Skill-card rendering 仍保留 collapse | deterministic rerender | **排除为唯一原因** |
| Query wording 单独导致 failure | rewrite control 无法复现完整 collapse | query-only rewrite | **不支持** |
| Agent end-task 得到提升 | collapse 实验没有 matched execution | 无 | **未证明** |

最值得保留的负结果是：5-shot repair 通常失败；MetaTool task-family split 也没有复现同样 collapse。Detector 只基于 19 个 source configurations，且 query-side 与 target-tool-side distance 强耦合。

## Field-map consequence

`tool registry → capability retriever → exposed action set → planner → execution`

它把故障点前移了一层：不是 planner 选错 tool，而是 gold tool 从未成为 admissible action。这个结论与 Agentic RAG 相邻，但当前最稳的范围仍是 ToolRet 的 executable capability retrieval。

地图状态为 `early_signal`，不能推广成“source-aware routing 是工具 agent 的稳定答案”。

## What remains unproven

下一步必须把 coverage 接到真实 execution：在 independent catalogs / live traffic 上比较 specialist、aggregate 与 routed mixture，同时匹配 checkpoint 训练维护、routing latency、tool-card tokens 与 planner budget。

只有当 gold coverage 和 task completion 同时改善，且 fixed aggregate 不再等价，routing 的系统价值才成立。
