# RetrievalRouter: Joint Modality and Architecture Selection for Document Retrieval

*发表于 2026-08-26 · 学习与优化 · 重要性 4/5 · 已阅读全文 · 置信度：中*

[论文](https://arxiv.org/abs/2608.25625) · [代码](https://github.com/emrekuruu/retrieval-router)

> **TL;DR.** RetrievalRouter 只看 query，就在 sparse/dense/rerank、text/multimodal 五种 pipeline 中选一个执行。它改善了在线 accuracy–latency frontier；但这个 frontier 没有把“同时维护所有底层 index”的 build/update/storage/cache 成本算进去。

| 30 秒判断 | |
|---|---|
| **为什么重要** | retrieval architecture 与 modality 不再是部署时常量，而成为 query-conditioned control surface。 |
| **最强证据** | `λ=0.1` 时 **0.755 nDCG@5 / 0.666 s**，best static ML 是 **0.737 / 8.283 s**；对 adapted hard-label router 是 **0.755 vs 0.715 nDCG**。 |
| **最大限制** | 需要同时保留四套 neural vector index + BM25；在线 latency 没有覆盖完整 lifecycle cost。 |

## Problem

同一 corpus 上，text/multimodal 与 dense/late-interaction pipeline 的失败是 query-dependent 的。固定一个 pipeline 会让简单 query 过度付费，也会让困难 query 用错 evidence-access substrate。

## Mechanism

`query → Qwen3-0.6B query encoder + linear head → BM25 / text-dense / text-rerank / multimodal-dense / multimodal-rerank → evidence`

训练时先离线运行所有 routing arms，得到每个 query 的 `nDCG × latency` reward vector，再用低温 soft target 而不是 hard best-pipeline label 训练 router。推理时只执行 router 选中的一个 pipeline，router overhead 约 15 ms。

## Closest comparison

最接近的控制不是单个 static retriever，而是论文把 Arabzadeh-style hard-label query router 扩展到同一五-pipeline action space。它同样做 query-level strategy selection，因此更适合回答“soft-target joint routing 是否有增量”。

## Decisive evidence

| 主张 | 证据 | 最近控制 | 判断 |
|---|---|---|---|
| 改善 static frontier | `λ=.1`: **0.755 / .666s** vs ML **0.737 / 8.283s** | best static | 强 |
| 改善 adaptive routing quality | **0.755 vs 0.715 nDCG** | adapted hard-label router | quality 增益，但 latency 更高 |
| latency-oriented 区间可能双赢 | `λ=.7`: **0.630/.148s** vs **0.624/.171s** | same adaptive baseline | 数值双赢，但未过论文 `p<.001` 阈值 |
| 仍有 routing headroom | oracle ≈ **0.90 nDCG** | per-query oracle | upper bound |

## What remains unproven

`online latency` 不是 `lifecycle cost`。要判断 router 真正省不省资源，需要在同一 corpus / recall target / traffic 下，把 multi-index router、single-index system 和 cascade 的 index build、incremental update、disk footprint、cache residency、router training 与 online latency 一起计价。

## Field-map consequence

`pre-retrieval adaptivity → query-conditioned pipeline routing → evidence acquisition`

这是 `early_signal`：它把“选哪个 retriever”推进为明确的 policy axis，但当前证据不足以说明 multi-pipeline routing 在完整资源口径上优于更简单的 single-index/cascade 设计。
