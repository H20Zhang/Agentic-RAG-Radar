# D2-ScaleAgent：把证据缺口分成“找新页”与“读深一点”

**中文** | [English](2608.16417.md) · [返回首页](../README.md) · [Research Library](../library/README.md)

[Paper](https://arxiv.org/abs/2608.16417) · **Importance: 3/5**

> **Research delta.** D2-ScaleAgent 不只是增加 agent 数量，而是让 Verifier 基于多粒度 Evidence Bank 判断：当前缺口需要**扩大 page coverage**，还是需要对已找到页面做**更细粒度 inspection**。

![D2-ScaleAgent 在检索广度与阅读深度之间路由](../assets/visuals/2608.16417.webp)

**如何读图。** Evidence Bank 是共享控制状态。Verifier 把 breadth gap 送往并行页面检索与 pruning，把 depth gap 送往 Surveyor / Locator / Extractor；新增证据写回后再次检查 closure。

**与什么比较。** 固定 multimodal RAG，以及没有在同一 state、operation set 和 resource budget 下匹配的 iterative seeker/inspector 系统。

**不要过度解读。** 图解释的是机制，不证明 Verifier 单独造成增益，也不证明 closure 一定正确或执行更便宜。

## Problem

长文档证据不充分时，系统能否区分两类原因：**相关页面尚未进入候选集**，还是**正确页面已经找到但尚未读到足够细**？

这比“要不要增加 test-time compute”更重要，因为它要求 controller 说明下一单位计算应该花在哪里。

## Mechanism

`initial retrieval → Evidence Bank → Verifier 判断 breadth/depth gap → 找新页或深读已有页 → 更新证据 → closure → answer`

- Breadth route：把缺口拆成最多六个加权 attribute query，并行检索、rank fusion、prune。
- Depth route：按 page / region / atomic evidence 粒度选择 Surveyor、Locator、Extractor。
- Retrieval 可以按候选集稳定性停止；回答由 evidence completeness 与 unresolved gap 共同约束。

真正被测试的是 **Evidence Bank + operation set + routing + 额外 adaptive compute 的组合**，不是一个孤立 Verifier。

## Closest comparison

最近的设计点是 S2G-RAG 的 sufficiency/gap state 与 RAAC 的 progress/stagnation control；D2 的最小增量是把缺口进一步路由成 page coverage 或 reading depth。最关键的实验对照是内部 verifier/removal ablation，而不是资源未匹配的端到端 baseline。

## Decisive evidence

| Claim | Evidence | Closest control | 判断 |
|---|---|---|---|
| 整体 adaptive package 有效 | 四个 base-model block 的均值均最高 | 固定/直接式长文档 baseline | 支持，但资源未匹配 |
| Verifier loop 是 load-bearing | MMLongBench-Doc **52.0 → 44.1** | 内部 ablation | 支持 package，不足以隔离 policy |
| Retrieval scaling 有贡献 | 去掉后 **52.0 → 46.8** | 内部 ablation | 当前 setting 支持 |
| Agent loop 总是更强 | Gemini VQA 在两个数据集反超 | direct VQA | **不支持** |
| 方法更高效 | 单个 profile 为 21.4K tokens / 16.22 s | 无 matched baseline cost | **未证明** |

Gemini direct VQA 的反超不是旁枝：它说明更复杂的 evidence loop 并不会自动战胜更强的整体模型。论文也承认多轮 retrieval 与分层 agent 会增加 latency/compute。

## Field-map consequence

`S2G-RAG 的 sufficiency/gap → RAAC 的 progress/stagnation → D2 的 breadth/depth allocation`

这是 `evidence-sufficiency routing` 的一个 **early signal**。它把“缺什么”进一步变成“应该扩 coverage 还是提高 inspection resolution”，但一篇组合式方法还不能形成稳定 map node。

## What remains unproven

真正 decisive 的实验应固定模型、page candidates、Evidence Bank、context delivery 与总 tokens/latency，只替换 router：

`fixed alternation ↔ random matched-compute routing ↔ heuristic gap routing ↔ Verifier routing`。

在此之前，结论应归给整体架构，而不是 Verifier policy 本身。
