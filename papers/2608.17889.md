# VisDocAgentBench: Benchmarking Agents for Visually Rich Document Retrieval

*Published 18 Aug 2026 · Evaluation & Analysis · Importance 3/5 · Full-text reviewed · Confidence high*

[Paper](https://arxiv.org/abs/2608.17889) · [Project](https://hulx2002.github.io/VisDocAgentBench/) · [Code](https://github.com/hulx2002/VisDocAgentBench)

> **TL;DR.** VisDocAgentBench gives static and agentic systems the same top-10 ranked-page endpoint, then tests whether direct, one-bridge, and two-bridge targets can be discovered in visually rich documents. It shows that strong one-shot visual matching can collapse on bridge paths and that iterative re-search plus page inspection help within one agent interface. It does not establish a universal policy win over the strongest static backend.

| 30-second verdict | |

| **Why this paper matters** | It evaluates iterative acquisition as retrieval—not only downstream QA—and separates discovery, inspection, evidence-role integration, and ranking. |
| **Strongest evidence** | Nemotron visual R@1 is **97.5% on direct items but 2.5% on two-bridge items**; removing iterative search from GPT-5.6-sol costs 8–9 R@1 points. |
| **Biggest caveat** | Agents use Qwen single-vector retrieval, not the strongest static Nemotron backend; the full loop also accumulates much more input context. |

## Research question

When target-page relevance is only visible through one or two hidden evidence bridges, what fails first: representation, target discovery, page examination, evidence-role integration, or final ranking?

This makes the endpoint important. Every system must rank page IDs, rather than hiding retrieval quality behind an answer-generation model.

## Research delta

The smallest delta is a **shared ranked-output benchmark for static and agentic visual-document retrieval**.

The corpus contains 2,375 pages from 100 scientific documents. The 120 unique-target queries are balanced across direct, one-bridge, and two-bridge structures. Bridge concepts, source IDs, titles, snippets, and page numbers are hidden; agents receive opaque handles and can rank only pages they discovered.

This is a benchmark/diagnostic contribution—not a new planner.

## Mechanism

**Acquisition loop.** `visual/OCR search → opaque page IDs → inspect/OCR/crop → reformulate from observed evidence → integrate bridge roles → rank top 10`

The visual and OCR routes expose analogous global search but different representations. Both allow page inspection; cropping requires prior inspection. Agents have 12 steps plus a ranking-only finalization call.

The most useful controls remove iterative re-search, page inspection, crop, or route-specific text. A support-provided intervention supplies the annotated evidence path, measuring what happens when acquisition succeeds.

## Evidence & attribution

| Claim | Evidence | Closest control | Assessment |
|---|---|---|---|
| Direct matching fails on hidden bridge paths | Nemotron R@1 **97.5% L1 →2.5% L3** | Same static retriever across levels | Strong in this corpus |
| Response-conditioned re-search helps | GPT-5.6-sol visual **61.67→53.33**, OCR **36.67→27.50** without iteration | Fixed top-30 inspection control | Supported, but context delivery differs |
| Page inspection is load-bearing | Removing it costs **15.84 visual / 21.67 OCR** R@1 | Same planner/interface family | Strong internal evidence |
| Cropping is generally helpful | Removing crop is +2.50 visual, −2.50 OCR | Crop ablation | **Not supported** |
| Agentic retrieval beats best static design | Backend mismatch: agent Qwen vs static Nemotron | No matched best-backend agent | **Unproven** |

The resource table prevents a cheap “fewer calls” story. GPT-5.6-sol visual uses 8.34 calls and 25.22 viewed pages versus 11 calls and 30 pages for the fixed control, but accumulates **177K versus 101K input tokens**. OCR is 248K versus 125K. Thus iteration may improve decisions while spending more history/context.

The failure map is also useful: the visual route discovers 83.3% of gold targets versus 58.3% for OCR; after correct discovery and inspection, final ranking is comparatively reliable. Support injection improves L2/L3, which establishes evidence-coverage sensitivity rather than controller quality.

## Where it fits

`static matching → explicit search/read interface → iterative acquisition → evidence-role integration → ranked target`

Together with CTIFoundry, this reinforces the Interface-resolution map: an evidence path needs explicit operations and an output contract that makes upstream failures visible. The two works are independent in domain and mechanism, but neither isolates a universal planner effect.

## Open question

The decisive benchmark extension would cross:

`static vs iterative policy × single-vector vs late-interaction backend × fixed vs accumulated context budget`

while preserving opaque handles, identical retrieved-card/page delivery, and equal total tokens/latency. A larger cross-document subset is essential; six items cannot stabilize the hardest claim.
