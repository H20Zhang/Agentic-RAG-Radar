# Agentic-R: Learning to Retrieve for Agentic Search

**arXiv:** [2601.11888](https://arxiv.org/abs/2601.11888) · **Published:** 2026-01-17 · **Category:** Learning & Optimization · **Importance:** 4/5 · **AI confidence:** Medium

**Tags:** `dense` `iterative search` `reinforcement learning` `open-domain QA` `multi-hop QA`

> **TL;DR.** Agentic-R trains retrieval for its role inside a multi-turn search trajectory, combining local relevance with downstream answer utility instead of treating the retriever as a frozen similarity service.


## Problem

A passage can be locally relevant yet be a poor action in a multi-step search trajectory. Once an agent repeatedly reformulates queries, the query distribution itself drifts away from the static retriever's original training regime.

## Core idea

Use both local passage relevance and downstream answer correctness to supervise retrieval utility, then iteratively train the retriever as the agent produces new search queries. Retriever behavior and agent query distribution co-evolve.

## Agent loop

`Reason → query → retrieve → update state/query → repeat → answer`

During training, outcome utility feeds back into retriever optimization.

## Retrieval design

Retrieval is treated as a learned component of the trajectory. The key question is not only whether a document is semantically similar to the current query, but whether retrieving it moves the whole search process toward a correct answer.

## Compared to what

Single-turn RAG retrievers, similarity-only retrievers, and agentic search systems that keep the retriever frozen while optimizing only the agent/reasoning policy.

## Evidence

The abstract reports consistent gains across seven single-hop and multi-hop QA benchmarks and multiple search agents. The radar has not yet re-checked exact tables, training cost, or stability/credit-assignment ablations.

## Why it matters

If retrieval is an **action** inside a sequential policy, training it only for static similarity is a misaligned objective. Agentic-R makes that mismatch explicit and points toward joint system design across retriever, query distribution, and trajectory objective.

This matters more if retrieval interfaces stabilize: once an agent has a clear operation/state API, learning can target the utility of whole information-acquisition trajectories rather than isolated passage scores.

## Limitations / questions

- How stable is iterative co-evolution of retriever behavior and agent-generated queries?
- How much of the gain comes from better retrieval versus changed query generation?
- What is the training/inference cost relative to a frozen strong retriever?
- Does trajectory-level utility transfer to different agent policies or retrieval substrates?

**Curator take:** **4/5**. Important because it aligns the retriever objective with agentic usage; exact causal attribution and training cost remain the main checks before calling the approach broadly reusable.
