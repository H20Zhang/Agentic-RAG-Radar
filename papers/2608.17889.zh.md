# VisDocAgentBench：把 Agentic Retrieval 本身变成可排名、可诊断的任务

**中文** | [English](2608.17889.md) · [返回首页](../README.md) · [Research Library](../library/README.md)

[Paper](https://arxiv.org/abs/2608.17889) · [Project](https://hulx2002.github.io/VisDocAgentBench/) · [Code](https://github.com/hulx2002/VisDocAgentBench) · **Importance: 3/5**

> **Research delta.** VisDocAgentBench 不再用最终 QA 掩盖 retrieval，而是让 static retriever 与 agent 都输出同一个 top-10 page ranking，并把失败拆到 discovery、inspection、evidence-role integration 与 ranking。

## Problem

One-shot visual retrieval 在“query 直接描述 target page”时可以很强，但 relevance 如果依赖一个隐藏 bridge，query-target similarity 就不再是完整任务。另一方面，普通 agent benchmark 只看最终答案，无法判断究竟是没找到页面、没检查、没理解 bridge role，还是最后排序错了。

## Mechanism

- 2,375 pages / 100 documents / 120 unique-target queries。
- L1/L2/L3 各 40，分别对应 direct、one-bridge、two-bridge。
- Search 只返回 opaque page ID 与 score，不给 title、source ID、page number 或 snippet。
- Agent 可以 visual/OCR search、inspect、OCR/crop，并且只能 rank 已经发现的 pages。

`search → opaque handles → inspect/OCR/crop → reformulate → integrate bridge roles → top-10 ranking`

## Closest comparison

论文把 static retriever 与 agent 都约束为 top-10 page ranking，这是比 final-answer benchmark 更接近因果诊断的 contract。最关键的内部对照是 no-search 与 no-inspection ablation；最强 static Nemotron 则不能作为纯 policy 对照，因为 agent 使用不同的 Qwen single-vector backend。

## Decisive evidence

| Claim | Evidence | Closest control | 判断 |
|---|---|---|---|
| Hidden bridge 会击穿 direct matching | Nemotron R@1 **97.5% L1 →2.5% L3** | 同一 static retriever | 当前 corpus 内强证据 |
| Iterative re-search 有效 | Visual **61.67→53.33**；OCR **36.67→27.50** | fixed top-30 control | 支持，但 history/context 不匹配 |
| Page inspection 很关键 | 去掉后 −15.84 / −21.67 R@1 | 同类 planner/interface | 强 internal evidence |
| Crop 总有帮助 | visual 反而 +2.50，OCR −2.50 | crop ablation | **不支持** |
| Agent 胜过最佳 static backend | Agent 使用 Qwen、最佳 static 使用 Nemotron | 无 matched control | **未证明** |

资源 accounting 改变了结论：full visual agent calls/pages 更少，但 input tokens 为 **177K vs 101K**；OCR 为 **248K vs 125K**。所以“更少调用”不等于“更低总成本”。

## Field-map consequence

这篇工作与 CTIFoundry 共同强化 Interface resolution：evidence path 需要可操作的 search/inspect/read surface，也需要固定 output contract 才能定位上游失败。

但它仍不是“agent policy 普遍优于 static retrieval”的证据：backend、accumulated context 与 resource budget 尚未正交化，而且真正 cross-document 的 query 只有 6 个。

## What remains unproven

下一版 benchmark 应做 factorial：

`static/iterative policy × single-vector/late-interaction backend × fixed/accumulated context budget`

并保持 opaque handles、delivery path 与总 tokens/latency 一致。否则 planner gain、retriever gain 与 history gain 仍会混在一起。
