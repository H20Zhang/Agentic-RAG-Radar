# When Tool-Backed Skill Retrieval Fails: Source-Style Collapse in Executable Capability Retrieval

*Published 17 Aug 2026 · Evaluation & Analysis · Importance 3/5 · Full-text reviewed · Confidence medium*

[Paper](https://arxiv.org/abs/2608.16502)

> **TL;DR.** A tool registry can stay fixed while a source-adapted dense retriever loses almost all gold-tool coverage on queries produced by other source conventions. ToolScout uses a query-side TF-IDF compatibility guard to keep safe traffic on a specialist and route unsafe traffic to a broad checkpoint. The failure is real on ToolRet; the current evidence stops before downstream agent execution.

| 30-second verdict | |
|---|---|
| **Why this paper matters** | Capability retrieval is an action-admissibility gate: a missed tool cannot be recovered by later planning. |
| **Strongest evidence** | The ToolRet-1100 specialist keeps **91.8%** matched coverage but falls to **22.3%** on the mixed stream; routing recovers **86.1%**. |
| **Biggest caveat** | A fixed aggregate retriever already gets **85.2%**; the result is coverage/proxy evidence, not end-to-end task success or a complete routing-cost comparison. |

## Research question

Can source-specific adaptation make executable-capability retrieval **less reliable on the same tool corpus**, and can a cheap compatibility signal detect when the specialist should not be trusted?

“Same corpus” is not “same retrieval distribution.” Query phrasing, schema references, verbosity, and how queries are paired with target tools can all change across source generators.

## Research delta

The smallest delta is a **source-compatibility routing guard** around capability retrieval.

ToolScout computes TF-IDF distance between incoming query traffic and the specialist's training source. Safe traffic stays on the specialist. Unsafe traffic switches to an aggregate-trained checkpoint. If matched labels become available, continuation tuning repairs the failed source.

The main scientific contribution is the failure mode and its boundary conditions, not a generally superior mixture-of-retrievers policy.

## Mechanism

**Control flow.** `query batch/window → source-compatibility score → specialist or aggregate retriever → top-20 tools → reranker → optional matched-source repair`

The paper carefully separates upstream candidate coverage from covered-query reranking. It also rerenders APIs as normalized executable skill cards, changes candidate depth, tests lexical fusion and staged decomposition, and probes second-corpus/query-rewrite boundaries.

## Evidence & attribution

| Claim | Evidence | Closest control | Assessment |
|---|---|---|---|
| Source-specific adaptation can collapse | FT-1100: **91.8% matched →22.3% mixed coverage** | Same checkpoint, fixed registry | Strong ToolRet evidence |
| A compatibility switch restores coverage | **22.3% →86.1%** | Unsafe specialist; fixed aggregate is 85.2% | Supported, but routing margin is small |
| Raw API schemas cause the failure | Skill-card rendering preserves collapse/switch | Deterministic rerender | **Ruled out as sole cause** |
| Query wording alone causes it | Query-only rewrites do not recreate natural collapse | Rewrite control | **Not supported** |
| Coverage recovery improves agents | No matched end-task execution for collapse study | None | **Unproven** |

Across five collapsed sources, 20 matched examples raise the coverage-weighted global top-1 proxy from 1.3% to 53.9%; five shots usually fail, and the hardest source remains below the aggregate reference even with more examples.

The detector itself is data-thin: only 19 source configurations underlie leave-one-configuration-out calibration. Query-side and target-tool-side distances are strongly coupled, so “source style” should be read as a source-conditioned query-tool distribution, not prose style alone.

## Where it fits

`tool registry → capability retriever → exposed action set → planner → execution`

Most agent papers evaluate from the planner onward. ToolScout shows that failure may happen one stage earlier: the correct action never becomes admissible. This is adjacent to document RAG but materially sharper because a missed capability removes executable behavior.

Its map status is `early_signal`: source-conditioned capability routing is not yet shown across independent catalogs, real online traffic, or factual document retrieval.

## Open question

The decisive next test needs live or replayable tool-use tasks with:

`specialist ↔ aggregate ↔ compatibility-routed mixture`

under matched training/hosting latency, retrieved-card tokens, and downstream execution. It should report both candidate coverage and actual task success, and isolate query wording from target-tool/source pairing.
