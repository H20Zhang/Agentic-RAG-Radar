# VAKRA：把 Retrieval 放进 Cross-Source Executable Trajectory 里评价

**中文** | [English](2608.12282.md) · [返回首页](../README.md) · [Research Library](../library/README.md)

[Paper](https://arxiv.org/abs/2608.12282) · [Code](https://github.com/IBM/vakra) · **Importance: 4/5**

> **Research delta.** VAKRA 不再把 API use、document retrieval、multi-hop reasoning 与 policy compliance 分开测，而是要求它们在**同一条可执行 trajectory**里保持 identity、evidence 与 policy 一致。

## Problem

一个 agent 可以分别在 API benchmark 和 document QA benchmark 上表现不错，但一旦真实任务需要：先从 document 找 entity → 调 API → 再用返回结果继续 reasoning → 同时遵守 tool-use policy，就会出现新的 failure mode。

典型问题包括 entity disambiguation、cross-source grounding、policy-constrained abstention，以及 tool execution 与 text evidence 不一致。

## Protocol / mechanism

VAKRA 的重点是 evaluation environment，而不是提出一个新 controller：

`interpret task/policy → choose API or document retrieval → execute tool/search → observe evidence → maintain cross-source identity/grounding → continue / abstain / answer`

Predicted tool calls 会在固定 harness 中重新执行，因此可以检查 trajectory，而不只是 final answer string。

## Closest comparison

最相关的 predecessor 不是某个 RAG method，而是把 API use、document retrieval、final-answer QA 分开测的 benchmark family。VAKRA 新增的是**composition**这个 evaluation object。

因此 leaderboard 结果首先是 system-level evidence：model reasoning、retrieval、tool policy、identity handling 与 stopping 都混在一起。

## Decisive evidence

论文报告最佳 evaluated model：

- single-hop endpoint-style task: **70.4%**
- compositional API setting: 约 **50–51%**
- 某些 policy-constrained unanswerable setting: 低至 **2.4%**

从 single-hop 到 composition 的明显掉点说明“每个 primitive 单独会做”远远不等于“整个 cross-source trajectory 能保持一致”。

## What remains unproven

VAKRA 暴露 failure，但不告诉我们应该改 retrieval policy、identity memory、planner、tool interface 还是 verifier。

最有判别力的下一步是固定 model、tool set 与 realized budget，只替换一个 control component，并在 hop-level trajectory 上定位修复了哪类错误。

还需要关注 policy wording、API availability、document snapshot 与 harness 对 score 的敏感性。

## Field-map consequence

RAG evaluation 的 unit 正从：

`retrieve relevant text`

扩展到：

`maintain coherent information state across heterogeneous access modes and executable actions`

这也是为什么它同时应该出现在 [Agent Benchmark Radar](https://github.com/H20Zhang/Agent-Benchmark-Radar) 的 RAG genealogy 中。
