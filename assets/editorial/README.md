# Editorial Research Visuals

This directory contains **reader-facing research visuals** used to make the radar faster to understand.

They are distinct from the canonical per-paper generated visual contract under `assets/visuals/`:

- `assets/editorial/` — lightweight field maps, icons, and grounded editorial diagrams that support navigation or evidence interpretation;
- `assets/visuals/` — canonical per-paper visual explainers governed by `VISUALS.md`, including PNG master + WebP delivery assets when marked generated.

## Editorial visual rules

An editorial visual must answer a concrete research question and be grounded in the same research interpretation as the surrounding Markdown.

Use editorial visuals for:

- field-level mental models;
- stable semantic icons;
- design lineages;
- causal/evidence diagrams;
- a second paper-specific view when it explains a **different** question from the canonical visual.

Do not use them for:

- decoration;
- repository/status dashboards;
- paper-count graphics;
- invented mechanisms;
- duplicated versions of the same figure.

Current visual grammar: near-white background, restrained blue/teal/neutral palette, simple geometry, thin lines, high whitespace, and short labels. A figure should read more like a strong research-paper overview than a product infographic.
