# Visual brief — A-RAG

**Renderer:** GPT-image-gen  
**Status:** pending generation  
**Grounding:** abstract/project-level; full-paper verification pending

## Visual question

How does A-RAG change the retrieval API from a fixed pipeline into a hierarchy of model-controlled operations?

## Grounded mechanism

Allowed elements:

- muted baseline: query → fixed retriever/top-k → context → answer;
- agent reasoning state;
- broad retrieval actions: keyword search and semantic search;
- fine-grained chunk read after candidate discovery;
- observation/evidence feeding back into the next tool choice;
- stop/answer when sufficient.

## Research delta to emphasize

**Retrieval becomes a small hierarchy of explicit actions under model control.** Broad candidate discovery and fine-grained reading should be visually distinct.

## Compared with

Single-shot RAG, fixed retriever pipelines, and hand-designed iterative RAG workflows.

## Do not imply

- Do not imply every query uses all tools.
- Do not imply the interface itself guarantees better performance independent of model capability/test-time budget.
- Do not invent tool internals or routing modules not verified in the radar record.

## Art direction

Wide before/after research explainer. Left: one narrow top-k pipe. Right: an agent state branching to two broad search operations, then a zoom/read operation, with evidence feeding back. Minimal labels: `keyword`, `semantic`, `read`, `evidence`, `answer`. No decorative robots or paper-figure imitation.
