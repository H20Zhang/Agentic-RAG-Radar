# Visual brief — SPARKLE

**Visual question.** What policy is learned by SPARKLE when the retriever and answer LLM are treated as the environment?

**Grounded mechanism.** At inference, show an answer-model reasoning state feeding a separate proxy policy. The proxy chooses `retrieve?`; if yes, it formulates a query, calls the retriever, integrates returned knowledge, and passes the updated state back to the answer model. Separately and more compactly, show training as `tree-structured trajectories → outcome reward → PPO update to proxy policy`.

**Research delta.** Visually separate the learned retrieval policy from the answer LLM/retriever. The key contribution is plug-and-play policy learning over retrieval decisions, query formulation, and knowledge integration—not another finetuned answer model.

**Compared with.** Prompted adaptive RAG and approaches that finetune/use the main answer LLM itself as the retrieval controller.

**Do not imply.** Do not imply the KG/proxy machinery is free, that PPO alone explains the gain, or that SPARKLE uniformly beats every RL search baseline under a matched answer model.

**Grounding status.** Full-text checked from ACL 2026 paper and official code repository.
