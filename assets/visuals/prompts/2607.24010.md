# Visual brief — When Should Active RAG Retrieve?

**Visual question.** Why can two Active RAG routers with the same nominal retrieval budget still be incomparable?

**Grounded mechanism.** Show a set of queries receiving router scores, then separate four audit lenses: `utility ranking`, `threshold → realized usage`, `retrieval harm`, and `trigger + retrieval + generation cost`. A nominal 50% target should visibly branch into different realized operating points rather than being treated as an equal-cost comparison.

**Research delta.** The evaluation object is the **operating point**, not one accuracy number or one trigger threshold. Exact matched-usage frontiers diagnose ranking; deployable thresholds diagnose calibration transfer; harm/cost audits explain why the same usage rate can still differ in value and compute.

**Compared with.** Single-point Active RAG evaluation at a nominal target budget without realized usage, harm, or trigger-side cost accounting.

**Do not imply.** Do not present BUR as a universally best router; the paper explicitly finds simple uncertainty/retrieval/query-complexity baselines competitive and router ordering changes by dataset/model/evidence source. Do not imply the controlled candidate-retrieval experiments are full open-domain search.
