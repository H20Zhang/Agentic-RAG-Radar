# Visual brief — SIRA

**Renderer:** GPT-image-gen  
**Status:** pending  
**Grounding:** full-text checked

## Visual question

When can corpus-aware retrieval-action compilation replace multi-round result-conditioned search?

## Grounded mechanism

Allowed elements:

- baseline: query → search → read result clues → reformulate → search again;
- SIRA: LLM predicts expected evidence vocabulary before reading results;
- corpus-statistic checks validate/prune proposed terms;
- surviving terms compile into a weighted BM25 action;
- final retrieval returns evidence;
- optional muted note that the main method also has offline corpus-side enrichment.

## Research delta to emphasize

**Move adaptivity upstream:** learn corpus vocabulary from index-visible signals and LLM priors before spending evidence-reading rounds.

## Compared with

Multi-round search agents and generic LLM query expansion over the same or similar retrieval substrate.

## Do not imply

- Do not imply one-shot search is universally better than iterative search.
- Do not hide the expensive offline document enrichment used in the main BEIR method.
- Do not imply Search-R1 is a fully matched same-backbone baseline.
- Do not imply BrowseComp-Wikipedia uses exactly one BM25 call in every case; it is evidence-blind and budgeted but may issue multiple category-grounded calls.
- Do not put benchmark values into the image.

## Art direction

Wide before/after interface explainer. Left side shows result-conditioned exploration; right side shows `predict → corpus check → compile → retrieve`. Keep 5–7 short labels: `search`, `read clues`, `reformulate`, `predict terms`, `corpus stats`, `compile`, `evidence`. No decorative robots or dashboard UI.
