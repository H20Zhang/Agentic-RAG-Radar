# Visual grounding brief — VAKRA (2608.12282)

**Visual question:** Where does a tool-using agent fail when it must compose executable APIs and document retrieval under natural-language policies?

**Grounded mechanism:** Show one query entering a fixed agent harness, branching between an API source and a document-retrieval source, then converging on cross-source grounding before answer/abstention. Highlight the failure boundary at entity disambiguation / cross-source grounding, not at API syntax alone. The benchmark verifies API actions by re-execution.

**Research delta:** The figure should teach **executable cross-source evaluation**: API interaction and document retrieval are evaluated in one trajectory under policy constraints instead of as isolated capabilities.

**Compared with:** API-only tool-use benchmarks, document-only RAG benchmarks, and final-answer-only evaluation without executable trajectory checks.

**Do not imply:** Do not present VAKRA as a new agent architecture, do not imply ReAct is optimal, do not invent an adaptive memory/controller module, and do not turn aggregate benchmark failures into a causal claim that retrieval alone is responsible. Keep benchmark numbers in Markdown, not the image.

**Grounding status:** Full paper checked on 2026-08-13; official IBM code repository verified.

**Preferred grammar:** Evidence/failure map. Use roughly 5–7 labels: `query`, `API`, `documents`, `policy`, `grounding`, `re-execute`, `answer/abstain`. One named paper only; no enterprise-dashboard UI.
