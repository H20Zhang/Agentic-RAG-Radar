# Visual brief — ReFind

**Renderer:** GPT-image-gen  
**Status:** pending  
**Grounding:** full-text checked

## Visual question

How can question-time retrieval control over the raw chat archive substitute for pre-built semantic memory structure?

## Grounded mechanism

Allowed elements:

- muted baseline: raw chat history → offline summaries/embeddings/tree/graph → retrieve memory → answer;
- ReFind: raw append-only chat turns stay intact;
- runtime agent issues lexical search with optional time scope;
- retrieval exposes session-aware ranking + local neighboring turns;
- previously inspected sessions are filtered across rounds;
- saved evidence feeds reformulation/stop, then a separate answer stage.

## Research delta to emphasize

**Move the intelligence from pre-question semantic memory construction into a stateful question-time retrieval interface over the faithful raw record.**

The figure should show the trade: less semantic preprocessing, more runtime interaction.

## Compared with

Structured memory systems and a matched generic multi-round BM25 agent without ReFind's chat-native controls.

## Do not imply

- Do not imply semantic memory structure is universally unnecessary.
- Do not imply BM25 alone explains the result; the generic-agentic BM25 control is materially weaker than the full interface.
- Do not imply every task needs multiple rounds; single-shot BM25 slightly beats ReFind on EventQA.
- Do not omit the question-time compute trade-off.
- Do not invent memory modules, embeddings, graph edges, or benchmark values inside the image.

## Art direction

Wide clean systems explainer. Contrast **precompute structure** with **preserve raw record + control at query time**. Use at most 7 short labels such as `raw chat`, `pre-built memory`, `search`, `session/time`, `local context`, `seen state`, `evidence`. No decorative robots or dashboard UI.
