# Agentic RAG Weekly — 2026-W32

> **Coverage:** 2026-08-03 to 2026-08-09 · **Status:** finalized, revised 2026-08-12 · **Adjacent context:** older work is included only where it changes how this week's papers should be interpreted.

## Week thesis

**W32 is a convergence and stress-test of Agentic RAG's control stack—not the origin of its component ideas.**

The week's papers make four variables unusually visible: **retrieval interface, evidence state, context policy, and resource allocation**. The backfill audit makes the thesis stricter: S2G-RAG already had an explicit sufficiency/missing-information controller in April; SPARKLE already compared a learned retrieval policy with other adaptive/search-RL systems; and budget-aware Active RAG evaluation shows that a nominal retrieval target is not itself a matched operating point.

The useful question is therefore:

> **What does the new system add after matching the information environment, explicit state, adaptive baseline, and realized resource budget?**

## Three durable shifts

### 1. State is becoming explicit—but August did not invent it

**READ** changes the primitive from dense top-k to lexical search, structural navigation, and bounded reads. **DocNavRAG** couples document-native navigation with collected/missing evidence state. **ACE-GraphRAG** makes context construction over a graph a policy.

But **S2G-RAG** is now the cleaner predecessor for explicit missing-information state: its judge predicts whether current evidence is sufficient and, if not, emits structured gap items that become the next query. Its no-judge ablation keeps retriever, maximum turns, per-turn top-k, and answer reasoner fixed while producing a large quality drop.

So DocNavRAG's more defensible delta is **document-structured environment + explicit evidence state co-design**, not the existence of missing-evidence state itself.

### 2. “Adaptive” is no longer an adequate baseline label

**SAGE** makes per-query passage budget a learned action under a latency SLO. That is a useful production control point, but its main comparison is static-k.

The backfilled **SPARKLE** paper raises the bar. It learns retrieval decision, query formulation, and knowledge integration in a separate proxy policy and directly compares against adaptive/search-RL baselines. The matched-generator results are competitive rather than uniformly dominant, which is exactly why the comparison is informative.

Future learned-controller papers should therefore state **which adaptive policy family** they beat, not simply “adaptive versus fixed.”

### 3. Budget is an operating point, not a number in the caption

**Know Before You Fetch** already separates retrieval calls, passage volume, and latency. **When Should Active RAG Retrieve?** makes a second distinction: a nominal target retrieval rate is not a matched budget until the held-out system actually realizes that rate.

It further shows why even matched evidence usage can hide different costs: uncertainty routers may pay for a no-retrieval generation before deciding, while retrieval-score routers may pay for a probe retrieval.

This turns budget matching into part of causal attribution rather than a reporting afterthought.

## Papers that matter most this week

**Forgotten History or Test-of-Time? — ★★★★☆.** Raises the novelty baseline to classical IR/QA; the caveat is that historical continuity is not technical equivalence.

**READ — ★★★★☆.** Shows that the retrieval primitive can dominate the agent loop; BM25 being statistically indistinguishable from READ is the most important negative result.

**DocNavRAG — ★★★★☆.** Makes document structure and evidence progress jointly controllable; after S2G-RAG backfill, its novelty should be read as environment–state co-design.

**SAGE — ★★★☆☆.** Makes k an SLO-aware learned action; useful systems framing, but static-k remains the main baseline family.

## Evidence audit

The minimum credible causal lens is now:

`substrate × operation set × state × policy × realized resources × base model × historical baseline`

Three failure modes remain especially dangerous. First, a better primitive can masquerade as a better agent. Second, explicit state can be credited for gains caused by a different environment or more retrieval. Third, nominally identical budgets can realize different usage and controller cost.

SPARKLE also removes one excuse: **strong adaptive-vs-adaptive comparisons are already feasible**, so static-only baselines should be treated as partial evidence when the claimed novelty is adaptive policy learning.

## Minimal reading order

For environment/state: **S2G-RAG → LLM-Wiki → READ → DocNavRAG**.  
For learned control: **SPARKLE → SAGE**, paying attention to what each actually holds fixed.  
For evaluation: **Know Before You Fetch → When Should Active RAG Retrieve? → Forgotten History or Test-of-Time?**.

## Questions to carry forward

1. Can one benchmark independently vary **environment, state, policy, and resources** without changing the answer model?
2. Can learned controllers beat **strong adaptive controllers at matched realized operating points**, not only static budgets?
3. Which modern gains remain after implementing strong historical IR/QA control loops with today's models and interfaces?
