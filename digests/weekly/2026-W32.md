# Agentic RAG Weekly — 2026-W32

> **Coverage:** 2026-08-03 to 2026-08-09 · **Status:** finalized, revised 2026-08-14 · **Adjacent context:** older work is included only where it changes how this week's papers should be interpreted.

## Week thesis

**W32 is a convergence and stress-test of Agentic RAG's control stack—not the origin of its component ideas.**

The week makes four variables unusually visible: **retrieval environment/interface, explicit state, adaptive policy, and resource allocation**. The historical backfill makes the chronology substantially stricter: by May–July, DCI, RISE, DR-DCI, and RARG had already turned corpus-interface resolution, bounded/dynamic interaction spaces, and relevance-guided interaction into explicit research objects. S2G-RAG already had missing-information state; SPARKLE already provided adaptive/search-RL baselines; Active-RAG evaluation already made realized usage/controller cost first-class.

The useful question is therefore:

> **What does a W32 system add after matching the corpus interface, harness, explicit state, adaptive baseline, and realized resource budget?**

## Three durable shifts

### 1. August interface papers sit inside a pre-existing interaction-space lineage

**READ** replaces dense top-k with lexical search, structural navigation, and bounded reads. **DocNavRAG** couples document-native navigation with collected/missing evidence state. **ACE-GraphRAG** makes graph context construction a policy.

But the stronger pre-August lineage is now visible. **DCI** showed that the bottleneck may be the resolution of the agent-facing corpus interface even after relevant documents are retrievable. **RISE** restored scale by making retrieval construct a persistent bounded interaction space. **DR-DCI** made that workspace dynamically expandable, and **RARG** reintroduced relevance as an execution prior inside interaction.

So the W32 delta is not “moving beyond top-k.” It is applying an increasingly mature environment/interface abstraction to structured document and context-policy problems.

### 2. Explicit state and learned control also have stronger predecessors

**S2G-RAG** predicts evidence sufficiency and structured missing-information gaps; its no-judge ablation keeps the retrieval budget/controller envelope much closer to fixed. This makes DocNavRAG's defensible delta **document-structured environment + evidence state co-design**, not missing-evidence state itself.

**SAGE** learns per-query passage budget under a latency SLO, but its main baseline family is static-k. **SPARKLE** shows adaptive/search-RL comparisons are already feasible, so future learned-controller claims need an adaptive-vs-adaptive baseline rather than a generic fixed-versus-adaptive story.

### 3. Evaluation needs both resource and harness matching

**Know Before You Fetch** separates retrieval calls, passage volume, and latency. **When Should Active RAG Retrieve?** shows nominal target usage is not the same as held-out realized usage and exposes controller/probe cost.

The backfilled **Is Grep All You Need?** adds a different confound: changing harness or tool-result delivery can materially shift—and sometimes reverse—grep-versus-vector conclusions. A retrieval result is therefore not cleanly attributable to the retriever if the surrounding evidence-delivery path changes.

## Papers that matter most this week

**Forgotten History or Test-of-Time? — ★★★★☆.** Raises the novelty baseline to classical IR/QA; historical continuity does not mean technical equivalence.

**READ — ★★★★☆.** Shows the retrieval primitive/interface can dominate the agent loop; BM25 being statistically indistinguishable from READ is the most important negative result.

**DocNavRAG — ★★★★☆.** Makes document structure and evidence progress jointly controllable; after stronger backfill, its novelty is environment–state co-design.

**SAGE — ★★★☆☆.** Makes k an SLO-aware learned action; useful systems framing, but static-k remains the main baseline family.

## Evidence audit

The minimum credible causal lens is now:

`substrate × corpus boundary/interface resolution × harness/delivery × state × policy × realized resources × base model × historical baseline`

Four confounds deserve explicit checks: a richer interface can masquerade as a better policy; harness/delivery can change retriever ranking; explicit state can be credited for gains caused by extra interaction budget; and nominally identical budgets can realize different calls/tokens/latency/controller cost.

## Minimal reading order

For interface chronology: **A-RAG → DCI → RISE → DR-DCI → RARG → READ / DocNavRAG**.  
For state/learning: **S2G-RAG → SPARKLE → SAGE**.  
For evaluation: **Is Grep All You Need? → Know Before You Fetch → When Should Active RAG Retrieve? → Forgotten History or Test-of-Time?**.

## Questions to carry forward

1. Can one benchmark independently vary **corpus interface, harness, state, policy, and resources** without changing the answer model?
2. When does relevance work best as a hard top-k boundary versus a workspace constructor versus an execution prior?
3. Which modern gains remain after implementing strong historical control ideas with today's models and interaction environments?
