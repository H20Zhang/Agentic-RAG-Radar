# Agentic RAG Weekly — 2026-W34

> **Coverage:** 2026-08-17 to 2026-08-23 · **Status:** rolling · **Current evidence through:** 2026-08-21

## Week thesis

**W34 turns retrieval design into placement plus operation-surface accounting.** Evidence may be materialized at query time (LENS), routed between page coverage and deep inspection (D2-ScaleAgent), exposed through visual or typed evidence-path operations (VisDocAgentBench, CTIFoundry), or fail before planning because the needed capability was never retrieved (ToolScout).

> A richer agent trajectory counts as a policy gain only after evidence/capability coverage, backend, interface, harness, accumulated state, and total token/tool/latency budget are matched.

## Three shifts

### 1. Explicit evidence-path operations gain cross-task support

VisDocAgentBench holds a top-10 opaque page output contract while testing iterative visual search and inspection. CTIFoundry keeps a stock mini-swe-agent but replaces flat corpus access with entities, relations, resolvable IDs, and typed `resolve / traverse / collect / read` tools. Together they reinforce the Interface resolution axis: evidence-path operations should be observable and testable.

The attribution remains bounded. VisDocAgentBench's full visual agent uses about 177K input tokens versus 101K for its no-iteration control, and its strongest static retriever uses a different backend. CTIFoundry's full treatment bundles corpus materialization, seven tools, tool descriptions, system prompt, and task skills.

### 2. Evidence sufficiency can route breadth versus depth

D2-ScaleAgent's verifier reads an Evidence Bank and decides whether to find another page or inspect a found page more deeply. On GPT-4o/MMLongBench, the full package scores 52.0 versus 44.1 without the verifier and 46.8 without retrieval scale.

This is one controlled signal, not a general direction: key controls lack matched costs, and Gemini direct VQA is stronger on both main benchmarks.

### 3. Capability coverage can fail before planning

ToolScout's specialist reaches 91.8% matched-source depth-20 coverage but only 22.3% on mixed sources; routed aggregation reaches 86.1%. A skill-card rerender does not remove the failure, and a small matched set sharply raises its global proxy.

The study stops before tool execution. It supports a capability-coverage audit upstream of planning, not an end-task routing claim.

## Placement and accounting

The expanded causal path is:

`evidence/capability exists → backend exposes it → interface permits path operations → controller allocates breadth/depth → retained state supports verification → answer/action`

LENS, RAAC, and the context-compression study remain important W34 context: moving work out of an index, search loop, or prompt can reappear as query-time localization, controller compute, or reacquisition.

## Evidence audit

**Strongest interventions:** D2 verifier/removal ablations; VisDoc no-search/no-inspection controls under the same page-output contract; CTIFoundry base/tools/skills/full grid; ToolScout matched/mixed/routed source tests.

**Unresolved confounders:** backend and history differences in VisDoc; bundled scaffold/tools/prompts/skills and missing online cost in CTIFoundry; unmatched adaptive compute in D2; no end-task execution in ToolScout.

## Reading order

**ToolScout → D2-ScaleAgent → VisDocAgentBench → CTIFoundry**: first verify candidate capability coverage, then route evidence acquisition, then compare visual and typed evidence-path operation surfaces.

## Questions carried forward

1. Do explicit evidence-path operations still help under the same backend, output contract, history, and total budget?
2. Can breadth/depth routing beat a compute-matched fixed policy?
3. Does source-conditioned capability routing improve executed task success, not only coverage?
