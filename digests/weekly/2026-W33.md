# Agentic RAG Weekly — 2026-W33

> **Coverage:** 2026-08-10 to 2026-08-13 · **Status:** rolling · **Adjacent context:** older anchors are included only when needed to interpret the week's delta.

## Week thesis

**W33 is pushing Agentic RAG from “what should I retrieve next?” toward two harder questions: “what if my accumulated state is wrong?” and “can I keep evidence coherent across heterogeneous sources?”**

LoongReflect makes **state recovery** explicit: reflection can remove a contaminated trajectory suffix rather than merely append another critique. VAKRA attacks a different boundary: API use and document retrieval are composed in one executable trajectory, exposing failures in entity identity and cross-source grounding.

The common theme is not another retrieval primitive. It is **trajectory integrity**.

## Two durable shifts

### 1. Explicit state is becoming editable, not merely descriptive

S2G-RAG and DocNavRAG already made sufficiency/missing-evidence state explicit. LoongReflect changes the control surface: the agent keeps a reversible trajectory tree, reflects on verified evidence and branch risk, and can backtrack to a trusted prefix while preserving a corrective lesson.

The important delta is therefore **rollback semantics + learned recovery policy**, not “agents can reflect.”

The evidence bar is also stronger than a static-baseline story. LoongReflect compares with Search-R1 and AgenticRAG-R1-class systems and reports large gains on seven RAG benchmarks. But the fast channel uses privileged global trajectory information during training, so the causal question remains whether the gain comes from reversible state, the learned controller, or privileged reflection supervision.

### 2. Evaluation is moving toward executable cross-source trajectories

VAKRA combines thousands of executable APIs, document retrieval, multi-hop composition, and natural-language tool-use policies under a fixed ReAct harness. Its strongest result is diagnostic: as tasks become compositional, failures concentrate around **entity disambiguation and cross-source grounding**, not basic API invocation alone.

That matters because most Agentic RAG evaluation still lets “retrieval,” “tool use,” and “reasoning” live in separate benchmark boxes. VAKRA shows a more realistic failure mode: each component may work in isolation while the evidence chain breaks at the boundaries.

The caveat is equally important. A fixed harness isolates model capability; it does not tell us which planning, memory, or retrieval-controller architecture would repair the failure.

## Evidence audit

LoongReflect provides unusually useful adaptive/RL baselines and component ablations, but its privileged teacher sees global trajectory information unavailable to the deployed student. Training-data selection also emphasizes recoverable failures. The result is strong evidence that the **whole recovery-learning package** works, weaker evidence for which component deserves the gain.

VAKRA provides executable tool-call checking and a fixed harness, which improves comparability. But its aggregate errors still bundle source selection, entity grounding, retrieval, policy interpretation, and synthesis. The next step is intervention-style replay: patch one intermediate decision and observe whether the trajectory recovers.

Together they add two axes to the radar's causal lens:

`state representation → state edit/recovery action → recovery supervision`

and

`single-source skill → cross-source trajectory integrity`.

## Most important papers

**LoongReflect — ★★★★☆.** Reversible active state plus reflection-specific credit assignment is a meaningful control abstraction; strong adaptive/RL baselines make the result more informative than a generic “reflection helps” claim.

**VAKRA — ★★★★☆.** Executable API+document composition under policy constraints exposes a failure surface underrepresented in document-QA benchmarks. It is an evaluation contribution, not a new agent architecture.

## Tension

The two papers should not be merged into one “long-horizon agents need memory” narrative. LoongReflect changes the **controller and state semantics**; VAKRA intentionally fixes the harness and diagnoses **model capability in a heterogeneous environment**.

A tempting inference is that rollback-style memory would solve VAKRA's cross-source failures. There is no evidence for that yet. Entity disambiguation and cross-source grounding may require better representations, schema alignment, or source-aware verification rather than trajectory rollback.

## Minimal reading order

**S2G-RAG → LoongReflect** to see the move from explicit missing-information state to editable/recoverable execution state.  
**VAKRA** next to test whether that abstraction survives an API+documents environment rather than QA-only retrieval.

## Questions to carry forward

1. Does reversible state still help when the dominant failure is **entity/schema grounding** rather than a clearly bad search branch?
2. Can we separate the value of a **rollback action space** from privileged recovery supervision under the same trajectory representation?
3. Can VAKRA-style executable benchmarks support **counterfactual replay** that patches one retrieval/control decision and measures causal recovery?
