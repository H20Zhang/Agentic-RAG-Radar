# Agentic RAG Monthly — 2026-08

> **Coverage:** 2026-08-01 to 2026-08-21 · **Status:** rolling · **Finalization:** after August closes

## Month thesis

**August is a placement-of-work and evidence-path story.** The field is not well described by `static RAG → agentic multi-round search`. Five variables must be separated:

`evidence/capability coverage × materialization time × operation surface × retained state × lifecycle resources`.

SIRA and ReFind separate pre-retrieval compilation from result-conditioned access. LENS moves evidence localization to query time. D2-ScaleAgent routes page breadth versus reading depth. VisDocAgentBench and CTIFoundry reinforce explicit evidence-path operations across visual documents and typed knowledge scaffolds. ToolScout shows that failure can occur before planning when candidate capabilities do not transfer across source distributions.

## 1. Evidence-path operations become a map-level interface axis

VisDocAgentBench tests static and iterative policies under the same top-10 opaque page delivery. CTIFoundry compares flat bash access with a scaffold exposing `resolve / traverse / collect / read` to the same stock agent. Their domains and treatments differ, but both make the route from query to inspectable evidence more explicit.

This reinforces, rather than replaces, earlier DCI/RISE/RARG/SIEVE work. The map tension is now:

`opaque top-k ↔ explicit search / resolve / traverse / inspect / read under a shared output contract`.

The boundary is causal: VisDoc changes backend and accumulated history in major comparisons; CTIFoundry bundles graph/entity materialization, typed tools, descriptions, prompt placement, and skills.

## 2. Adaptivity has more than one placement

SIRA compiles a discriminative action before reading passages. ReFind adapts from names, times, and local context revealed by prior results. D2 adds a narrower online decision: whether current evidence calls for another page or deeper inspection of a found page.

D2's verifier ablation is useful, but one paper does not establish a broad routing direction. A decisive comparison would fix page candidates, reader, model, and total tokens/calls/latency while varying only breadth/depth allocation.

## 3. Retrieval can fail before the controller acts

ToolScout adds capability coverage to the causal lens. A planner cannot select a tool absent from its candidate set, and a retriever that works in one source style may collapse on a mixed source. Routed aggregation restores much of the measured coverage, but end-task execution is missing.

The useful order is:

`evidence/capability exists → candidate retrieval → interface delivery → agent inspection/planning → execution`.

## 4. State and removed work still have a price

RAAC exposes progress/stagnation state; LoongReflect makes active reasoning state reversible; SGR-Bench exposes external retrieval state. The context-compression study shows that dropping queryable state can create repeated retrieval while completion stays flat. LENS shows that avoiding a persistent index shifts work into online localization.

Therefore “fewer search calls,” “no index,” and “smaller context” are incomplete without controller, localization, reacquisition, update, token, tool, and latency accounting.

## Causal synthesis

The current lens is:

`substrate/evidence coverage × capability coverage × pre-retrieval observability × materialization × backend × operation surface × source/environment state × harness/delivery × retained agent state × policy × realized resources × base model × training protocol`.

A packaged trajectory gain should not be attributed to retrieval or planning until the first unmatched factor is located.

## Evidence audit

Strongest evidence comes from matched or factorized contrasts: ReFind's generic-agentic and one-search controls; RAAC's same-agent overlays; LENS's stale-index/sequential ablations; the compression paper's oracle restoration; D2's verifier/removal cells; VisDoc's search/inspection ablations; CTIFoundry's base/tools/skills/full grid; ToolScout's matched/mixed/routed source tests.

Main gaps are equally concrete: unmatched online work, changed retrieval backends, accumulated-history differences, bundled operation surfaces and prompts, missing update lifecycles, and proxy-only rather than executed outcomes.

## Open problems

1. Match backend, output contract, accumulated history, and total budget when testing evidence-path operations.
2. Separate new-page coverage from deep inspection and charge verifier cost.
3. Measure capability recall before planning and executed success after routing.
4. Account for offline construction/update plus online tokens, tools, context, and latency.
5. Counterfactually repair one evidence-path failure and test whether the trajectory recovers.
