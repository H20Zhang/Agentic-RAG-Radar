# Agentic RAG Monthly — 2026-08

> **Coverage:** 2026-08-01 to 2026-08-12 · **Status:** rolling · **Finalization:** after August closes

## Month thesis

**August is not the origin of agent-native retrieval; it is the point where several control variables are becoming easier to separate.**

The strongest current map is:

`retrieval environment/interface → evidence state → policy/stopping → resource allocation → evaluation`

READ, DocNavRAG, and ACE-GraphRAG sharpen the middle of this stack. SAGE adds per-query retrieval budget as a learned systems action. Two backfilled anchors change the interpretation: **LLM-Wiki** already made the agent-facing environment argument explicitly in May, while **Know Before You Fetch** established a disciplined June baseline for graded retrieval-budget allocation and cost accounting. The new IR-history perspective then pushes the novelty baseline back another two decades.

So the interesting August shift is **convergence + factorization**, not “RAG suddenly moved beyond top-k.”

## Emerging field map

### 1. Environment and interface become first-class design objects

A-RAG exposes keyword/semantic/read operations. LLM-Wiki compiles documents into linked pages and gives the agent search/read traversal. READ exposes lexical search, structural navigation, and bounded reads. DocNavRAG turns document-native structure into a navigable environment.

The research question is no longer “which retriever wins?” but:

> **What is the minimal sufficient information-access interface for the task and substrate?**

LLM-Wiki gives the cleanest current causal support for this direction: keeping the compiled Wiki but disabling progressive traversal reportedly causes an 11.7–13.8 F1 drop. READ supplies the opposite warning: BM25 is statistically indistinguishable from READ in its reported setting. Together they imply that **substrate/interface quality and adaptive policy must both be ablated**; neither should be credited by default.

### 2. State and budget become explicit controller variables

DocNavRAG tracks collected/missing evidence rather than relying only on implicit reasoning history. ACE-GraphRAG makes context assembly over a rich representation query-dependent. Know Before You Fetch and SAGE make **how much retrieval** an explicit decision rather than a fixed global knob.

This expands the control state from “what should I search next?” to:

`what is known? → what is missing? → what operation? → how much resource? → stop?`

The cost vocabulary also has to become more precise. Know Before You Fetch shows that retrieval-call rate, full-context rate, passage budget, and measured latency can move differently; its confidence probe can even make gating slower on a smaller reader. SAGE's SLO framing is useful, but the next comparison should be adaptive-vs-adaptive, not merely learned policy versus static k.

### 3. Evaluation now needs a historical as well as causal baseline

The IR-history perspective argues that iterative retrieval, query reformulation, answer verification, and constraint relaxation have concrete classical QA antecedents. QUALIFIER's successive-constraint-relaxation loop is an especially relevant precedent.

This adds a seventh axis to the radar's evaluation lens:

`substrate × operation set × state × policy × budget × base model × historical baseline`

The last axis does not imply “nothing is new.” It asks **where the novelty actually lives**: richer model state, learned control, better interfaces, transfer, scale, or a genuinely new action space.

## What older anchors now look different

- **A-RAG** remains the clean early-2026 interface anchor, but LLM-Wiki shows a richer compiled-environment version with strong traversal ablation.
- **Search-o1** is best read as reasoning-time retrieval control; newer work asks what explicit evidence state should replace raw trajectory history.
- **Graph-R1 / Agentic-R** become more meaningful once interface, state, and budget are treated as explicit action spaces to learn over.
- **PlanRAG** is still useful for plan-first control, but classical IR/QA reminds us that iterative reformulation itself is not novel.

## Most important papers in the current map

### LLM-Wiki — ★★★★☆ · older anchor, newly backfilled

**Lasting idea:** compile knowledge into an agent-facing traversal surface and test structure separately from progressive traversal.

**Caveat:** benchmark corpora are bounded subsets; compilation and large-scale maintenance remain open systems costs.

### Beyond Top-K / READ — ★★★★☆

**Lasting idea:** retrieval primitive and agent policy must be evaluated separately.

**Negative result:** BM25 matching READ weakens a generic “agent beats RAG” conclusion.

### DocNavRAG — ★★★★☆

**Lasting idea:** co-design document-native navigation with explicit evidence-progress state.

**Open attribution:** structure vs state vs variable retrieval budget.

### Know Before You Fetch — ★★★★☆ · older anchor, newly backfilled

**Lasting idea:** retrieval budget has multiple resource axes; calibrated confidence can select no/compact/full retrieval or abstention.

**Negative result:** compact retrieval does not automatically reduce retrieval-call rate, and gating is not universally faster once the probe cost is counted.

### Forgotten History or Test-of-Time? — ★★★★☆

**Lasting idea:** novelty evaluation should include classical IR/QA lineage.

**Caveat:** historical continuity is not technical equivalence; QUALIFIER's causal advantage is inferred rather than ablated.

### SAGE — ★★★☆☆

**Lasting idea:** retrieve-depth can be a learned SLO-aware resource action.

**Caveat:** strong fixed-k frontier result, but adaptive-k/stopping baselines are missing from the main experimental comparison.

## Core tension

The current field can produce the same headline “adaptive RAG wins” from very different causes:

1. better information substrate/interface;
2. better state representation;
3. better policy/stopping;
4. more intelligently allocated compute/context.

Those are different research contributions. A strong paper should make at least one of them identifiable rather than changing all four at once.

The historical lens adds a second tension: **a control pattern can be old while its modern implementation is still important**. The burden is to say what changed materially.

## Evidence audit

**Strongest evidence this month:** LLM-Wiki's structure-vs-traversal ablation; READ's BM25 negative result; Know Before You Fetch's separated cost axes; SAGE's explicit SLO/latency measurements.

**Weakest recurring point:** adaptive systems are still too often compared with static or weak controllers. Matched primitives and matched resource axes are becoming the minimum credible standard.

**Coverage warning:** long-/multi-document QA dominates. Transfer to web research, SQL/data analysis, code, scientific search, and multimodal evidence is still mostly an open claim.

## Open problems

1. **Minimal sufficient retrieval API:** what operations are necessary without making control brittle?
2. **Explicit information state:** evidence coverage, uncertainty, provenance, and missing requirements need cleaner representations.
3. **Adaptive-vs-adaptive evaluation:** strong budget/stopping policies should be compared on identical substrate/hardware/cost axes.
4. **Resource-aware learning:** calls, tokens, latency, and money should enter the policy objective explicitly rather than only the reporting table.
5. **Historical baseline discipline:** modern work should isolate what LLM-era capabilities add beyond older closed-loop IR/QA principles.

## Minimal reading path

**Environment/interface:** A-RAG → LLM-Wiki → READ → DocNavRAG.  
**State/context policy:** Search-o1 → DocNavRAG → ACE-GraphRAG.
