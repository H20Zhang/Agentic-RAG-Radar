# Agentic RAG Monthly — 2026-08

> **Coverage:** 2026-08-01 to 2026-08-17 · **Status:** rolling · **Finalization:** after August closes

## Month thesis

**August is a factorization story, but the newest correction is about where adaptivity lives.** The field is no longer well described by “static RAG → agentic multi-round search.” Some useful control can be **compiled before retrieval** from corpus-visible signals; some must remain **result-conditioned** because the next information need only appears after evidence inspection.

The current map is:

`evidence availability → pre-retrieval corpus observability/action compilation → interface/boundary → result-conditioned control → environment + agent state → realized resources → training protocol → executable evaluation`

SIRA provides the pre-retrieval counterpoint; ReFind provides the runtime-interaction counterexample. DCI/RISE/DR-DCI/RARG and SIEVE still explain interface resolution and scalable boundaries. LoongReflect adds reversible state; VAKRA adds cross-source trajectory integrity. Training Protocols pushes the causal baseline one step earlier: **the external corpus must actually contain answer-bearing evidence before retrieval-learning reward is meaningful.**

## 1. Retrieval is now about adaptivity placement, not round count

The interaction-space lineage remains:

`top-k evidence delivery → raw high-resolution interaction → bounded/dynamic workspace → relevance-guided interaction`

But SIRA and ReFind reveal a second axis.

**SIRA** predicts evidence vocabulary, validates it with document-frequency/index signals, and compiles weighted lexical retrieval before reading result passages. Its BEIR results show that a strong programmable retrieval action can remove some need for exploratory rounds. The caveat is systems-level: the main setup also pays for offline LLM corpus enrichment, and its BrowseComp-Wikipedia advantage is model/budget dependent.

**ReFind** makes the opposite bet for chat memory: preserve raw turns and use question-time lexical reformulation plus session/time/local-context controls. Its matched generic-agentic control shows that iteration alone is insufficient; its one-search control shows that result-conditioned iteration can still matter when new evidence exposes names, times, or sessions useful for the next query. EventQA slightly favors single-shot BM25, so the effect is workload-dependent.

The stable question is therefore:

**What discriminative information is observable before the first retrieval, and what only becomes observable after inspecting evidence?**

## 2. Interface resolution remains a separate systems variable

Pi-Serini shows that backend tuning, surfaced ranking depth, and browsing affordances can make a lexical baseline look artificially weak. DCI shows the complementary failure: even when relevant documents are reachable, a top-k interface can hide useful local operations. RISE/DR-DCI restore scalable boundaries; RARG brings relevance back inside the interaction space. SIEVE then separates candidate admissibility, ranking, inspection, and selective reading.

This prevents a new false binary. SIRA is not “retrieval wins”; DCI/ReFind are not “agents win.” They occupy different points in **corpus observability × action expressivity × online interaction cost**.

## 3. State has multiple owners

S2G-RAG and DocNavRAG maintain internal evidence/sufficiency state. LoongReflect makes active reasoning state editable through rollback. DR-DCI persists external workspace state.

SGR-Bench adds a different layer: **environment retrieval state**. The agent may reach the correct source yet expose the wrong evidence because filters, views, hierarchies, scopes, or time windows are wrong.

These should remain distinct:

`external source state ≠ persistent evidence workspace ≠ internal evidence/reasoning state`.

A rollback policy cannot fix a source that is still configured to the wrong scope; a correct source state does not guarantee the agent preserves the right evidence history.

## 4. Learning claims now depend on retrieval-environment validity

SearchMaster showed that the self-generated training distribution is itself causal. Retrieval, Reward, and Training Protocols strengthens the point: **training data can be unanswerable from the retrieval corpus while final-answer reward remains positive because the model knows the answer parametrically.**

That means reward design is downstream of a more basic validity check: can the external information channel support the labeled task at all?

The same controlled study also weakens “finer process reward is better.” Simple outcome reward remains competitive in several matched settings; process rewards trade supporting-document recall, redundancy, and search depth rather than uniformly improving them. Longer train/eval search budgets can also reduce final accuracy.

## 5. Evaluation has to trace the whole information path

The current causal lens is:

`substrate/evidence coverage × corpus boundary/interface resolution × environment retrieval state × harness/delivery × agent state × policy × realized resources × base model × training distribution/protocol × historical baseline`

The practical ordering matters more than the number of axes:

`evidence exists? → backend exposes it? → agent can inspect it? → source is in the right state? → controller chooses well? → harness preserves it? → evidence remains coherent across sources?`

Pi-Serini, SGR-Bench, Is Grep All You Need?, Training Protocols, and VAKRA each isolate a different break in this chain.

## Core tension

The month now has two coupled trade-offs:

**Compression vs control.** Retrieval compresses a huge corpus; interaction preserves exact local operations. Too much compression hides useful actions; too little destroys scale.

**Precompute vs query-time adaptation.** SIRA spends more knowledge/corpus work before evidence retrieval; ReFind keeps the record simple and spends more search/LLM work when the question arrives. Neither side is free. A credible comparison must count offline construction/update cost, query-time calls, latency, context, and evidence fidelity together.

## Evidence audit

The strongest current evidence comes from matched or near-matched contrasts: SIEVE's Search–Fetch control; ReFind's generic-agentic and one-search controls; SearchMaster's same-backbone self-play ablations; Training Protocols' corpus/reward/tool/budget grid; Is Grep All You Need?'s harness comparisons.

SIRA is informative but not perfectly controlled against every agent baseline; Search-R1 differs in backbone and BrowseComp-Wikipedia changes available corpus structure. Pi-Serini's strongest tuning/depth ablations are on a 100-query subset. LoongReflect's privileged teacher weakens component attribution. VAKRA diagnoses failures but does not identify which controller would repair them.

## Open problems

1. **Adaptive placement:** predict when a query should use compiled pre-retrieval control versus result-conditioned multi-round search under matched total compute.
2. **Layered state repair:** independently intervene on external source state, persistent workspace, and active reasoning state.
3. **Training-environment validity:** audit evidence coverage before optimizing retrieval rewards or self-generated curricula.
4. **Backend × interface × harness factorial evaluation:** hold model/corpus/resources fixed while swapping one information-access variable at a time.
5. **Counterfactual trajectory repair:** patch one intermediate failure and measure whether the final answer causally recovers.
