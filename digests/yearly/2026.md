# Agentic RAG Yearly — 2026

> **Coverage:** 2026-01-01 to 2026-08-25 · **Status:** rolling · **Scope note:** this is a year-to-date map over papers currently curated by the radar, not a claim of complete historical coverage.

## Year-to-date thesis

**The durable 2026 shift is from treating Agentic RAG as “an LLM plus a retriever” toward explicitly deciding where information-acquisition work should live.** The important system objects are no longer only retriever quality and number of search rounds, but:

`what evidence exists × what can be observed before retrieval × what is materialized before the query × what operations the interface preserves × what new information appears only after evidence inspection × what state persists or can be repaired × where displaced work is paid`.

The most useful unifying tension is:

**`precompute / materialize / retain ↔ defer / localize / reacquire`**.

A system can spend work on corpus enrichment, indexing, structured memory, persistent workspace, or retained state; or it can preserve a rawer substrate and buy information later through query-time localization, repeated retrieval, controller compute, or state reacquisition. Neither side is inherently more agentic or cheaper. The systems claim only survives when offline and online work are counted together at matched answer/evidence quality.

## What changed from the start of the year

Early 2026 work could still be described reasonably as moving retrieval into the agent loop. Agentic-R trains a retriever for trajectory-level utility, A-RAG makes retrieval operations explicit, and the Agentic RAG SoK frames retrieval as a sequential decision process.

By mid-year, that description became too coarse. DCI and its descendants showed that the **retrieval interface itself** determines what evidence operations an agent can express. SIRA then showed that some apparent runtime adaptivity can be compiled before evidence inspection when corpus-visible signals are available. ReFind supplied the opposite boundary: result-conditioned interaction matters when earlier retrieval reveals names, times, or session-local cues needed by later queries.

W34 adds two further corrections. LENS makes **evidence materialization time** explicit: evidence regions over changing raw documents can remain latent until the query arrives. RAAC makes **search progress** explicit: coverage, novelty, query diversity, and drift can drive continue/redirect/stop. The context-compression study makes **recoverability** explicit: dropping queryable state can leave completion unchanged while forcing the agent to buy that state back through many more retrieval calls.

The map therefore ends up broader than `static RAG → multi-round agentic search`:

`evidence validity → corpus observability/materialization → agent-facing interface → result-conditioned control → environment + agent state → progress/recovery/retention → lifecycle resources → training protocol → executable evaluation`.

## Durable shift 1 — retrieval becomes an interface and materialization problem

A-RAG exposes a hierarchy of retrieval actions. DCI makes raw corpus operations such as grep/find/read a first-class interface, showing that strong reasoning cannot recover evidence hidden by a lossy top-k surface. RISE and DR-DCI restore scalable corpus boundaries while preserving high-resolution local interaction, and RARG keeps relevance active inside that interaction rather than using it only to filter candidates.

SIEVE sharpens the factorization further: candidate admissibility, ranking, pre-read inspection, and reading granularity are separate controls. Pi-Serini raises the baseline bar from another direction: “BM25” is not a controlled baseline unless backend tuning, surfaced depth, and agent inspection affordances are specified.

LENS adds a different placement decision. Indexed RAG materializes evidence units before the query; DCI preserves raw files but exposes fixed local operations; LENS treats candidate evidence windows as query-conditioned latent objects. Its negative result is essential: ReAct has higher answer EM on the controlled D500 comparison and is nearly tied on fullwiki. The cleaner claim is freshness and evidence localization/grounding, bought with more online work—not universal answer-quality superiority.

**What survived:** retrieval quality cannot be separated from **what the agent is allowed to observe and manipulate, and when evidence structure is materialized**.

## Durable shift 2 — adaptivity has a location

SIRA challenges the lazy equation `more search rounds = more intelligence`. It predicts evidence vocabulary, grounds it with corpus statistics, and compiles a weighted lexical action before reading result passages. ReFind gives the counterexample: on raw chat history, matched one-search and generic multi-round controls are weaker when later queries need cues revealed by earlier retrieval.

The durable variable is therefore:

`information available before retrieval ↔ information revealed only by retrieved evidence`.

If discriminative corpus structure is already observable, runtime exploration can be wasteful. If a later action depends on a newly discovered entity, timestamp, relation, or contradiction, result-conditioned interaction is genuinely informative.

Neither paper establishes a universal winner. SIRA pays substantial offline corpus-side work in its main setup and has a backbone/budget reversal on BrowseComp-Wikipedia; ReFind avoids semantic preprocessing but pays multiple searches and LLM calls per question and has an EventQA cell where single-shot BM25 slightly wins.

**What survived:** round count is an outcome of where information becomes observable, not a capability metric.

## Durable shift 3 — state becomes layered, observable, editable, and priced

S2G-RAG separates `evidence sufficient?` from `what is missing?` and uses structured gaps to drive the next query. DocNavRAG couples evidence state to document-native navigation. RAAC adds progress/stagnation state—coverage, document novelty, query diversity, and drift—to decide whether search should continue, redirect, or stop. LoongReflect makes active reasoning state reversible through explicit reflection/backtracking and recovery supervision.

SGR-Bench adds an external boundary: the agent can find the right source and still fail because filters, views, hierarchy, scope, or time window leave the environment in the wrong retrieval state.

The context-compression study adds the missing systems property: **state has a reacquisition price**. At 5× compression, retrieval rises in all six model-regime cells while completion changes are not significant; restoring dropped queryable state removes most of the extra interaction. ALFWorld is the crucial counterexample: the same compression does not create a retrieval surge when relevant state is cheap to re-observe.

The useful separation is:

`environment retrieval state ≠ persistent evidence/workspace ≠ evidence/progress state ≠ active reasoning state ≠ retained context`.

StateMem adds **operative-state validity** inside that separation. Its strongest evidence is not the persistent package's leaderboard gain, but a matched answer-time wrapper control: with transcript, retrieved chunks, call count, intermediate length, and answer format held fixed, chronological value chains and precedence rules add 15.0–31.7 points on StateMemBench. The boundary is equally important: the benchmark is synthetic, persistent ingestion uses hundreds of LLM calls, dependency propagation sometimes hurts, and external LongMemEval structure gains are small or negative with DeepSeek.

**What survived:** less retained context is not automatically less work. State policy must be evaluated by `retention cost ↔ expected reacquisition cost`.

## Durable shift 4 — learning claims move upstream into environment validity

Agentic-R changes retriever training toward trajectory utility. Critic-R uses reasoning dissatisfaction for query repair and retriever supervision. GrepSeek learns direct-corpus actions. SearchMaster makes the self-generated task distribution itself a controlled object. LoongReflect learns recovery behavior.

But Retrieval, Reward, and Training Protocols exposes a prerequisite that is more fundamental than reward design: **can the retrieval environment actually support the target answer?** The study finds thousands of training questions without answer-bearing corpus evidence while the model can still receive positive final-answer reward through parametric knowledge. Tool format, rollout protocol, and search budget also materially change learned behavior; finer process reward does not uniformly dominate simple outcome reward.

SearchMaster adds the complementary lesson for self-improvement: a policy can optimize against a bad self-generated curriculum. Evidence-chain grounding, minimum successful search depth, and over-opening penalties improve the quality of the training distribution rather than merely changing the inference controller.

**What survived:** “better search-agent RL” is not one variable. The learned object and the environment/curriculum that produces supervision must be identified separately.

## Durable shift 5 — evaluation becomes a causal path with lifecycle accounting

The current causal lens is:

`substrate/evidence coverage × pre-retrieval corpus observability × materialization/interface resolution × environment retrieval state × harness/delivery × agent state/retention × policy × realized offline+online resources × base model × training distribution/protocol × historical baseline`.

The ordering matters:

`does evidence exist? → can the backend/environment expose it? → can the agent inspect/manipulate it? → is source state correct? → does retained state preserve what matters? → does the controller choose well? → does the harness preserve the evidence? → what work was actually spent?`

Training Protocols, Pi-Serini, SGR-Bench, Is Grep All You Need?, VAKRA, and the context-compression study each isolate a different failure in this chain. Forgotten History or Test-of-Time? adds the historical constraint: query reformulation, verification, and iterative retrieval are not automatically novel because an LLM now executes them.

W34 contributes a practical accounting rule: **whenever a paper removes something, look for where the work moved**.

- no persistent index → charge query-time localization/oracle work;
- fewer search calls → charge controller/re-thinker work;
- fewer context tokens → charge state reacquisition/tool work;
- no semantic memory construction → charge question-time search and synthesis;
- richer offline corpus observability → charge construction/update cost.

**What survived:** efficiency is a lifecycle property at matched quality, not a single local metric.

## New August stress tests — allocation, materialization, and causal diagnosis

The latest papers mostly sharpen boundaries rather than create new durable nodes. ASCP shows that **freshness over rounds** can dominate fixed reuse, while its feedback scheduler is tied with strong rotation and their matched resource delta is unreported. Its 17.5s-versus-1.7s cost contrast instead compares sequential `(2,12)` with one-shot `(24,1)`. Scroll shows that lossless retained state can be queried and selectively materialized, while its closest CodeAct comparison leaves only a small unique increment. GTA-RAG, SSE-Bio, CAS, and MCite-RL each place learning at a different control point—evidence chain, source choice, retrieval width, and visual localization—but their strongest claims come from within-package ablations, not heterogeneous leaderboard gaps.

AgenticRAG-FP adds a useful evaluation principle: once a retrieval fault changes later actions, causal origin may require a live intervention rather than a post-hoc label. Its survivor-conditioned matrix is too narrow for a durable depth claim, but it makes one year-to-date rule more concrete: **evaluation must preserve and manipulate the causal path, not only inspect the final trajectory**.

## Ideas that weakened

**“Agentic means more retrieval rounds.”** SIRA and ReFind show opposite regimes; the correct variable is when useful information becomes observable.

**“No index means less work.”** LENS buys freshness/localization with more query-time compute. Offline work can move online rather than disappear.

**“Fewer searches means a cheaper agent.”** RAAC saves search calls but adds controller, coverage-updater, and critical re-thinker calls that must be charged.

**“Smaller context means lower runtime cost.”** Context compression can triple retrieval-like reacquisition while task completion appears unchanged.

**“Better retriever means better information access.”** DCI, Pi-Serini, SIEVE, and ReFind separate backend recall, admissibility, inspection, local navigation, and substrate-native controls.

**“Found the source means retrieval succeeded.”** SGR-Bench shows the source can still be in the wrong retrieval state.

**“Finer RL reward means better search policy.”** Training Protocols shows evidence coverage, tool format, off-policy degree, and budget can dominate or reverse the conclusion.

## Evidence audit

The strongest year-to-date evidence comes from **matched or factorized interventions**, not heterogeneous leaderboard wins: S2G-RAG's judge ablation, SIEVE's Search–Fetch control, ReFind's generic-agentic and one-search controls, RAAC's same-agent overlay comparisons, LENS's stale-index/sequential-exploration tests, context compression's oracle restoration, and Training Protocols' controlled corpus/reward/tool/budget grid.

The recurring weaknesses are equally stable. Many papers still change interface, model, tool budget, and controller together; production-scale latency/cost is often represented by a local proxy; evaluation remains QA-heavy; and frontier-model/harness changes can dominate nominal method differences.

Important negative boundaries should remain visible: LENS does not beat ReAct on main answer EM; RAAC's search-call savings omit controller compute; SIRA has a model/budget reversal; ReFind has a one-shot-friendly task; LoongReflect uses privileged teacher information; context compression does not reproduce its retrieval surge in ALFWorld.

## Open problems entering the rest of 2026

1. **Lifecycle-matched placement.** Under the same changing corpus and total compute, where is the crossover among persistent indexing, compiled retrieval actions, bounded direct interaction, and query-time evidence localization?
2. **Recoverability-aware state retention.** Which state atoms should remain resident because expected reacquisition cost exceeds context/memory cost?
3. **Progress-aware control with total-cost accounting.** Do continue/redirect/stop controllers still win when their own LLM calls, latency, and tokens are charged?
4. **Semantic–symbolic interface co-design.** How much corpus structure/statistics should be exposed before retrieval without recreating a lossy hard top-k bottleneck?
5. **Training-environment validity.** How should corpus answerability, self-play curriculum quality, reward, and rollout protocol be audited before search-policy optimization?
6. **Factorial executable evaluation.** Can benchmarks swap backend, interface, environment state, retained state, harness, and controller independently while supporting counterfactual repair?
7. **Cross-substrate generalization.** Do these abstractions survive APIs, SQL, code, multimodal archives, private memory, and live web search rather than text QA alone?
