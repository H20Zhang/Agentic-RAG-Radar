# Agentic RAG Yearly — 2026

> **Coverage:** 2026-01-01 to 2026-08-11 · **Status:** rolling · **Scope note:** this is a year-to-date map over papers currently curated by the radar, not a claim of complete historical coverage before the radar's backfill matures.

## Year-to-date thesis

**The durable 2026 shift is that Agentic RAG is becoming less about attaching an agent to a retriever and more about designing an explicit information-acquisition control stack.** Across the strongest current design points, the recurring objects are becoming separable: the retrieval substrate, the operations exposed to the agent, the state used to represent evidence progress, the policy that chooses the next action, and the objective used to learn or evaluate the trajectory.

The important caveat is causal attribution. Better agentic systems frequently change several of these axes simultaneously, so a higher final QA score does not by itself show that the adaptive policy caused the gain.

## Durable shifts so far

### 1. Retrieval is becoming an interface, not a single call

A-RAG, READ, and DocNavRAG make the action surface itself a research object: keyword/semantic search, bounded reads, structural navigation, or data-native graph operations can be explicitly exposed rather than hidden behind one `top-k(query)` primitive.

**Old default → new design point:** one generic retrieval API → a small composable operation set.

**Why this looks durable:** the same idea appears across flat documents, structured long documents, and graph-like environments.

**Counterargument:** READ's BM25 result shows that a better non-agentic primitive can explain much of an apparent agentic gain. Interface quality and policy quality must be separated experimentally.

### 2. Retrieval progress is becoming explicit state

Search-o1 already moved search into the reasoning trajectory. Newer work such as DocNavRAG sharpens the abstraction by representing what evidence has been collected and what remains missing, instead of relying only on raw reasoning history.

**Old default → new design point:** implicit state in the prompt/trajectory → explicit evidence/progress state.

**Why this matters:** state can potentially become a stable systems interface across different retrieval substrates.

**Counterargument:** there is not yet enough matched-budget evidence showing that explicit state beats a strong controller using raw context alone.

### 3. Context construction is becoming a policy

ACE-GraphRAG and Graph-R1 make a clean distinction between what a rich representation makes reachable and what a query-time policy actually chooses to retrieve. Agentic-R extends the same logic into training: retrieval should be optimized for trajectory-level usefulness rather than static similarity alone.

**Old default → new design point:** fixed context assembly / independently trained retriever → adaptive or learned trajectory policy.

**Counterargument:** policy gains remain entangled with richer action spaces, more retrieval calls, different base models, and larger context budgets.

## Papers that currently define the 2026 map

1. **A-RAG** — clean retrieval-interface abstraction: explicit search/read operations under model control.
2. **Agentic-R** — retrieval objective moves from local relevance toward trajectory utility.
3. **READ / Beyond Top-K** — strongest current warning that retrieval primitive can dominate the apparent benefit of agentic composition.
4. **DocNavRAG** — environment + explicit evidence-state co-design.
5. **ACE-GraphRAG** — context assembly over a rich representation becomes an adaptive policy.

Older anchors such as Search-o1, Graph-R1, and PlanRAG remain important for understanding how the control boundary evolved into the 2026 design space.

## The evaluation standard that 2026 is forcing

The most useful common lens is:

`substrate × operation set × state × policy × budget × base model`

A credible claim about the **policy** axis should increasingly control or ablate the others. In particular, the field needs more primitive-matched, budget-matched, and explicit-state ablations rather than comparisons where every component changes at once.

## What is still under-tested

- transfer of the same retrieval interface/state abstraction across documents, web, SQL, code, graphs, and multimodal evidence;
- trajectory quality and stopping quality under matched calls/tokens/latency;
- whether learned policies generalize across retrievers and base agents;
- whether multi-agent orchestration adds coordination value rather than simply spending more inference budget;
- benchmarks that expose tool-selection, state, routing, verification, and stopping failures separately.

At year end, the finalized report should remove transient ideas that did not survive and add a dedicated section for claims that weakened or failed to generalize.
