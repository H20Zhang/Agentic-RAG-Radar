## Accepted

### Beyond Top-K: Replacing Black-Box Retrieval with Interpretable Agentic Operations

`Retrieval & Tool Use` · ★★★★☆ · arXiv:2608.06305

**TL;DR.** READ replaces embedding top-k with replayable lexical-search, structural-navigation, and bounded-read operations that an agent composes over raw long documents.

**Agent loop.** `Lexical search → structural navigation → bounded read → inspect → refine → answer`

**Why it matters.** The strongest result is an interface ablation: using the same agent loop with a top-k tool performs substantially worse, suggesting that iteration alone cannot rescue a poor retrieval primitive. Equally important, the authors report BM25 as statistically indistinguishable from READ, so the evidence supports an embedding-vs-lexical/interface claim more strongly than an agentic-vs-non-agentic claim.

[Paper](https://arxiv.org/abs/2608.06305)

### DocNavRAG: Document-Structured Graph RAG with Stateful Evidence Construction for Complex Document Question Answering

`Retrieval & Tool Use` · ★★★★☆ · arXiv:2608.01565

**TL;DR.** Turn document hierarchy and cross-region relations into the agent's retrieval environment, then track collected and missing evidence as explicit state across navigation actions.

**Agent loop.** `Locate → navigate/expand → fetch → update evidence state → identify missing evidence → continue/answer`

**Why it matters.** The interesting claim is environment–policy co-design: instead of learning a better policy over flat chunks, expose structure already present in documents as retrieval operations. The abstract reports average gains of 7.8% in answer quality and 17.7% in context sufficiency across four long-/multi-document QA benchmarks; component-level attribution still needs full-paper checking.

[Paper](https://arxiv.org/abs/2608.01565)

### ACE-GraphRAG: Agentic Context Engineering for Hierarchical GraphRAG

`Iterative Reasoning & Verification` · ★★★★☆ · arXiv:2608.01269

**TL;DR.** Make hierarchical GraphRAG context assembly an inference-time policy that can retrieve depth-oriented factual evidence or breadth-oriented semantic evidence and adapt choices per query/topology.

**Agent loop.** `Initial context → detect gap → choose depth/breadth branch → retrieve → consolidate → adapt → generate`

**Why it matters.** Hierarchical representation does not imply useful context. ACE-GraphRAG makes the missing layer explicit: a policy that maps a query and graph topology into a context-construction trajectory. A full-paper pass should check whether gains survive matched retrieval/token budgets.

[Paper](https://arxiv.org/abs/2608.01269)

## Screened but not promoted

**RH-RAG: Trustworthy Long-Form Generation for Privacy-Constrained Settings** (arXiv:2608.01311) is clearly an agentic multi-stage RAG system, but from the abstract its main contribution appears to be planner/writer/checker orchestration for long-form generation rather than a new agent-controlled retrieval policy. It is therefore held out under the radar's stricter inclusion criterion unless a full-paper read shows retrieval control is a substantive contribution.

## Daily synthesis

The three accepted papers point to the same deeper shift: **the research object is moving from “which retriever?” to “what retrieval interface/state should an agent control?”** READ changes the operation set, DocNavRAG changes the environment and evidence state, and ACE-GraphRAG changes context assembly into a policy. This is more consequential than simply putting an LLM loop around top-k retrieval.
